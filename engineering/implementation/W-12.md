## 局部對照與限制

650 組功能案例分別在固定 arm64 與 i386 PHP 8.5.12 映像執行，Go runtime 比對全部 1,300 組的有序型別值、警告嚴重度／訊息與例外種類／訊息。原有 102 組案例保留，新增案例包括長度 2～40 的固定比較回傳、完整比較序列、超過 16 與 1024 的分界、混合型別、uasort 保留鍵與中途拋例外。來源與輸出雜湊見[排序修正證據](evidence/W-12-sorting-php8512.json)。

每個 by-ref 迭代器為候選副本分別保存位置，選定副本後清除其他候選。同一陣列的下一次取值不會只因有副本而提早分離，以免把前一輪元素的暫時持有誤認成永久別名。真正寫入時才依當時的參照關係分離。已釋放陣列及結束／中斷迭代會解除位置登錄。

位置範圍與 Go slice 容量分開保存，以對照 PHP 8.5.12 在稀疏整數鍵轉混合鍵、壓縮空洞及分離副本時的指標結果。讀取 current／key 不會提前跳過並改寫原始指標。排序持有獨立參數參照，callback 解除綁定或重新綁定原變數時，仍更新原參數位置。空陣列排序保留下一索引。上述情境均有固定映像的回歸案例，沒有依賴 Zend 的記憶體布局。

`matrix.php --destructor-probe` 與 `--unsafe-reentry` 是獨立的參考引擎診斷。兩者在固定 arm64 映像均以 exit 133、`zend_mm_heap corrupted` 結束，i386 映像則正常結束。這些結果單獨記錄，不計為相容通過，也沒有轉成 skip。Go 的直接物件換綁以仍有效的舊位置執行必要解構，另外用所有權、安全重入與錯誤清理測試驗證，不複製參考引擎的記憶體損毀。完整物件圖釋放、復活與弱參照的正式整合由 W-13 負責。

本票維持 PHP 8.5.12 的局部語意，不代表歷史版本已驗證。型別化屬性限制由 W-13 物件模型整合。參照參數／回傳、來源位置與 VM 呼叫由 W-17 整合。正式公開 SDK 由 W-24 整合。T-013／014、T-031／032、T-033／034 的完整驗收負責票分別為 W-24、W-17、W-41。resource 鍵及 resource 失效操作等待 resource 模型，不以本票案例宣稱通過。

排序的比較順序、參數方向、次數及例外後部分排列均屬於相容契約。Go 實作依 PHP 8.5.12 的小陣列排序、插入排序與混合排序執行，並以原始位置補救相等比較。比較拋錯後停止呼叫使用者函式，內部排序仍依穩定補救完成部分排列。固定回傳正數、負數、零與不具遞移性的比較也須一致。衍生部分的完整授權與來源見 [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md) 及來源清單，不以專案 MIT 授權取代上游授權。

使用者排序在獨立副本執行並提交至保留的參數參照。內建排序先分離再就地排序，不額外重新賦值。內建排序的比較期間以鍵讀取同一陣列會得到未定義（arm64、i386、amd64 固定映像都回報 `Undefined array key 1`），`count()` 與 iteration 仍看得到全部元素，`usort()` 的比較函式則讀得到原陣列。`sort()` 這類重新編號的排序在比較期間只交換值，鍵留在原位（`zend_hash_bucket_renum_swap`），`asort()` 這類保留鍵的排序則把鍵和值一起交換，所以在 `__toString` 裡 foreach 同一陣列，`sort()` 看到 `0=a,1=S,2=c`，`asort()` 看到 `1=a,0=S,2=c`。排序因此以位置操作，由呼叫端決定交換時搬動什麼。`TestW12SortKeyLookupDuringComparisons` 與 `TestW12SortIterationDuringComparisons` 固定這些行為。非陣列引數的 TypeError 依 PHP 寫出函式名稱與值的型別，例如 `sort(): Argument #1 ($array) must be of type array, true given`，資源不論是否已關閉都寫 `resource`。排序與指標函式因此接收 PHP 函式名稱 `op`，`uksort()` 的 bool 回傳棄用訊息也依此命名。PHP 8.5.12 對物件呼叫 `current()`、`reset()` 等指標函式只發出 `Calling current() on an object is deprecated` 並讀取屬性，Phego 仍回傳 TypeError，這項屬於 W-13 的物件屬性走訪，尚未實作。空副本保留下一索引但重設初始化狀態及迭代位置，混合表示移除空洞時不重新映射迭代位置。這些差異均有固定映像案例，未複製 Zend 的配置器。

每次 callback（包含 bool 反向重試）都重讀元素的參照位置，分別持有當次參數。回傳值先取得持有權，再釋放當次參數，避免借用的物件提前解構。重試關閉 heap 後不再轉型或呼叫診斷，仍保留原始錯誤並釋放回傳值。callback 與 deprecation 處理函式修改別名的案例皆對照固定映像，關閉 heap 與回傳物件生命週期另有 Go 安全回歸測試。

參數清理的解構函式拋錯時，仍保留 callback 已產生的有效比較結果，但不再發出診斷或反向重試。初次比較與重試對巢狀 deprecation 狀態的影響分開處理。兩種固定映像已驗證六種回傳型別及巢狀警告次數。多個物件解構例外的主例外替換與 previous 鏈尚未建立，由 W-13 物件生命週期與 W-17 例外整合負責，不宣稱完整物件例外語意已完成。

bool 回傳的補救位於 `ext/standard/array.c` 使用者比較包裝層。`sortArrayUserWithDiagnostic` 已提供 Go 掛點：false 反向呼叫一次、每次排序的 deprecation 狀態、巢狀排序重設狀態，以及診斷處理函式拋例外後的部分排列。回傳參照包住 bool 時直接轉型，不套用 bool 補救。物件與浮點回傳轉型的警告也經相同診斷掛點。W-17（issue #21、PR #77）負責接上正式 VM 呼叫、PHP 錯誤處理函式及取消；W-13（issue #18、PR #73）負責尚未建立的物件／enum 內建比較。這些是下游整合責任，不是已接受的排序差異。

核心操作沒有外部 I/O。callback 接受並傳遞錯誤，但不可中斷的宿主 callback 與正式配額／取消接線由執行層負責。heap 仍由單一請求循序擁有，不支援多個 goroutine 同時修改。

## 輸入、狀態與失敗處理

本票測試以 PHP 8.5.12 固定參考映像與 heap 的 32／64 位元設定選擇語意。完整入口的 profile、能力與資源上限驗證由後續執行層整合。可變陣列、參照、迭代位置與診斷均屬於當次 heap。
