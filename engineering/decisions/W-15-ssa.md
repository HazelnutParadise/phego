# W-15：保留 PHP 語意的值 SSA

對應 REQ-016、REQ-024、REQ-034、REQ-054，以及 T-031、T-032、T-047、T-048、T-067、T-068、T-107、T-108。

## 表示與分析

`internal/ir/ssa` 接收 W-11 的唯讀 `ir.Unit`。每次運算出現各有一個 `uint32` ID，零表示缺少的運算元。PHP 變數、參照、陣列元素、動態作用域與控制流程保留原始操作。沒有提升變數，也沒有跨基本區塊的純量傳播，因此不需要合併變數值的 phi 節點。這是保留結構化控制流程的值 SSA，尚不是完整的控制流程 SSA。

值表依建圖順序儲存，**不是執行排程**。後端必須由函式 roots 進入，依 HIR 規則選擇分支、短路與迴圈，不能依 ID 順序執行整張表。函式參數預設值與類別 initializer 是定義範本，不能在建圖或快取命中時執行。

型別資訊只對運算正常完成後的結果成立。分析不相信參數的型別註記就把讀值當成整數，而是從 literal、cast、isset、比較等操作取得確定結果型別。所有位置讀寫均保留，故不依賴不完整的別名精準度。`extract`、`compact`、`$$x`、參照參數與捕捉不會被純量化。

效果重新聯集 operands，保留額外標註。未知操作與使用者 callback 採完整效果集合。`Ordered` 額外表示位置讀取、控制、配置與安全操作不可刪除或重排。本輪沒有重排、死碼移除或共同運算消除，因此不新增多條記憶體 token 或失效分析框架。它們只有在具體的後續 pass 需要移動操作時才有必要。

來源使用有界的 64 位元類別聯集，最高位元表示未知。來源不明的變數、呼叫、物件及 closure 預設未知。明確的 `Sources[n]=0` 只表示該節點自行引入的來源已確認可信，不能清除 operands 的標記。摺疊結果仍保留原始節點、檔案、行號及子邊。這份編譯 metadata 不代表 W-21 的請求內字串區段追蹤已完成。

## 最佳化開關

| Pass | 可處理的操作 | 保留條件 |
|---|---|---|
| `FoldConstants` | 可精確表示的整數加減乘、整數位元操作與正負號、布林否定、字串與字串串接、非浮點純量嚴格相等 | 運算元均為無效果常數，沒有位置 flags、呼叫、額外效果或超額字串配置 |
| `SpecializeTypes` | 已證明布林值的否定、已證明整數 operands 的 `&`、`|`、`^` | 原 operands、順序及效果全部保留，不推論未知變數 |

`Passes=0` 關閉兩項最佳化。溢位、浮點、NaN、除法、冪次、字串強制轉換、複雜值與其他操作沿用通用路徑，沒有取消這些 PHP 功能。整數摺疊依 guest 的 32／64 位元範圍，不能使用宿主 `int` 寬度，也不能假設溢位不會發生。型別特化是給後續 lowering 的證明資訊，整數位元 replay 仍用現有 runtime helper，沒有新增另一套 PHP 語意。

`Build` 檢查精確 profile、取消、節點與容器項目總量、深度及新增常數字串總量。取消、無效輸入、節點或深度超限回傳錯誤與 nil Program；新增常數字串額度不足只放棄該次摺疊，保留通用操作。深度上限至多 1024，額度先於配置檢查。包含沒有預設值的參數、空項目、重複宣告清單及每次 closure 的 captures。Program 不包含請求 static、環境、session、活物件、執行回饋或失敗狀態。`CheckProfile` 核對 release、guest 整數寬度與 short_open_tag，拒絕跨 profile 重用。本票沒有新增編譯快取。

## 選項與實測

採用 Go 原生 slices 的密集值表。常見的一至兩個 operands 直接放在記錄內，較大的操作才使用共用 ID slab。邊長度沿用不可變 HIR，刪掉重複的三個 `int` 欄位。沒有 `unsafe`、cgo、LLVM、每值 heap 物件或請求物件池。

比較過逐值指標節點、全部 operands 都使用 slab、以及目前 inline2／slab 的表示。逐值指標增加 GC 可掃描邊與配置次數。完整 CFG、變數提升與可重排的多效果鏈在本輪沒有必要的收益，反而增加 alias、例外與解構時機的證明負擔。分支仍由原 HIR 控制，沒有引入第二套控制流程。

原始樣本在 [evidence/W-15-ssa](/docs/implementation/evidence/W-15-ssa)。命令為：

```sh
go test ./internal/ir/ssa -run '^$' -bench BenchmarkW15 -benchmem -count=3 -benchtime=200ms
```

本機為 Apple M3、darwin/arm64、Go 1.26.5。儲存建構 microbenchmark 固定 512 個值，每值兩條往前的邊，不包含分析：

| 表示 | B/op | allocs/op | 三次 ns/op |
|---|---:|---:|---|
| 全部 slab 候選 | 53,392 | 3 | 4,752、5,175、4,495 |
| inline2／slab | 41,120 | 2 | 2,663、2,652、2,636 |
| 逐值指標 | 40,960 | 512 | 8,275、8,294、8,228 |

三個候選都保留在 `BenchmarkW15Storage`，可用相同命令重測。inline2 的記憶體比逐值指標多 160 bytes 的 Program 容器，但配置次數少 510 次。已直接採用移除重複欄位、常見邊內嵌及 closure captures 單次掃描，不將沒有額外成本的改善留作取捨。

完整 Build 另量測常數、cast 後整數與 opaque 控制／呼叫三種來源，分別記錄 off/on 的時間、記憶體及配置。最佳化有編譯成本，不能由儲存 microbenchmark 推論 PHP 程式或網站較快。樣本含背景負載，沒有宣稱 VM、AOT 或競品速度收益。

## 驗證與保留限制

固定 arm64 與 i386 PHP 8.5.12 映像各產生 285 案，包括 256 組固定種子隨機算式。每案比較 off、只開常數、只開特化及全開的結果、PHP 例外、警告層級／訊息／行號及 callback／解構輸出。測試 adapter 使用現有 W-10、W-12、W-14 核心，明確拒絕未實作的操作。它不是產品 VM。

CI 每次重新執行兩個固定映像，逐位元組比對已提交參考，再以對應 guest 寬度 replay。fuzz 另比較 runtime 的 off/on。政策、配額與取消節點的順序測試屬編譯契約模型，不宣稱完整後端政策整合已通過。

W-11 效果表同時補上零底數負冪、NaN 布林／字串轉換、插值、輸出與條件轉換的診斷可能性。未知操作不再因 map 缺項而變 pure。獨立審查找到的容器額度漏算及 nil capture panic 均先重現，再修正並保留回歸測試。

W-17 的 VM、W-21 的實際來源追蹤及 W-37／W-39 的原生後端整合尚未驗收。W-11 登錄的編譯期常數診斷缺口亦未因本輪運算 pass 自動消失，包含 `(1+1)::class` 與常數陣列串接警告，仍保留於 `internal/ir/corpus_gaps_test.go`。本票不宣稱完整 PHP 編譯相容或任何產品情境通過。
