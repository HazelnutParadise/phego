# W-17 differential VM fixtures

`cases/*.php` are small PHP programs for the first Phego VM stages. Each one runs in the pinned PHP 8.5.12 images and in Phego, and stdout, displayed errors, logged errors and exit codes must match byte for byte. The references are oracle data, never product acceptance.

Fixtures use only the syntax the VM stages up to 7A support: echo, print, literals, simple interpolation, variables, operators, casts, `isset`/`unset`/`empty`, array literals, array element reads and writes (compound assignment, increment and decrement, nested and appending writes, nested `unset`), `foreach` by value and by reference, assignment by reference, destructuring (`[...] =`, `list()`, keyed, nested, by reference, in `foreach`), string offset reads, control flow, `match`, `@`, `exit`/`die`, top-level and namespaced user functions with parameters by value or by reference, constant-expression default values and a variadic parameter, calls with positional, named and unpacked arguments, `global` and `static` variables, top-level `const` declarations, the predefined constants of `php -n`, magic constants, and top-level `return`. The stage-2 groups are named `array_elem_*`, `foreach_*`, `param_default_*` and `string_offset_*`; the stage-3 groups, for references, are `ref_*`, `foreach_ref_*` and `param_ref_*`; the stage-4 groups, for destructuring, are `list_*` and `foreach_list_*`; the stage-5 groups are `const_*`, `magic_*`, `match_*`, `empty_*` and `silence_*` (`match_jumptable_folded_conditions`, `fatal_match_lines_folded_expression`, `const_namespace_fallback_cache`, `match_folded_operands_and_elements`, `const_default_fallback_cache` and `const_expr_predefined` are the regression fixtures of the two stage-5 reviews); the stage-6 groups are `global_*`, `static_*`, `variadic_*`, `unpack_*` and `named_*`, `call_callee_declared_later` covers the line a plain variable argument gets when PHP compiles a call before it knows the callee, and `call_callee_known_lines` is the regression fixture of the stage-6 review; the stage-7A groups, for classes and objects, are `class_*` (declarations, inheritance, interfaces, traits, constants, static properties), `object_*` (creation, comparison, casts, iteration, nullsafe), `method_*` (calls, late static binding, visibility), `prop_*` (declared, typed, readonly and dynamic properties, array writes, references), `type_*` (parameter and return types in weak and strict mode) and `magic_method_*` (constructors, destructors and their order, `__get`/`__set`/`__isset`/`__unset`, `__call`/`__callStatic`, `__toString`, `__invoke`, `__clone`); `review7a_*` are the regression fixtures of the stage-7A review; their uncaught-error, compile-error and parse-error variants start with `fatal_`. They call no builtin functions (so no `define()`), name no builtin class other than `stdClass`, use no closure, `try`, `throw`, enum or property hook (later stages), read no resource constants (STDIN) and no platform-dependent ones (CHAR_MAX, PHP_BUILD_DATE), and they must not depend on time, memory, hash order or host paths. A case that needs anything else waits for a later stage.

A case may override INI values for all three modes with comment lines right after its opening tag, one per line, such as `// ini: error_reporting=30717`. `reference.php` passes them to `php -n` as `-d` after the mode's flags and the Go harness passes them as `WithINI`, so a case can show what `@` and plain diagnostics do under a different `error_reporting`.

`reference.php` runs inside the container. For each case, in sorted order, it starts `php -n` with stdin closed, working directory `/w` and the script at `/w/cases/<name>.php`, in three modes that all set `html_errors=0` and `error_reporting=-1`:

- `display`: `display_errors=1`, `log_errors=0`
- `log`: `display_errors=0`, `log_errors=1`, `error_log=` (the CLI writes bare `PHP Warning:  ...` lines to stderr, without a timestamp)
- `both`: `display_errors=1`, `log_errors=1`, `error_log=`

Cases named `return_*` run a fourth time through `include`, and the top-level return value is recorded as JSON text in `return_json` (`JSON_PRESERVE_ZERO_FRACTION`). Every other case has `return_json: null`.

Regenerate a profile with `python3 tests/vm/w17/reference.py --width 64 --write` (arm64, `reference-64.json`), `--width 32 --write` (386, `reference-32.json`) or `--width 64 --arch amd64 --write` (`reference-64-amd64.json`). Without `--write` the script regenerates and fails on any drift from the committed file. 386 and amd64 run under emulation on Apple Silicon and take several minutes.

Each reference file holds `php_version`, `int_size`, `os`, `machine`, `image`, `platform`, the scrubbed `command`, `inputs_sha256` and `cases`. Each case holds `case`, `source_sha256`, `display`, `log` and `both` (each with `stdout_b64`, `stderr_b64` and `exit_code`) and `return_json`. `machine` is the kernel's name (a 386 container reports `i686` under emulation and `x86_64` on an x86_64 kernel), so drift comparison skips it.
