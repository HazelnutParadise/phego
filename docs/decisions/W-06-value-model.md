# W-06 值、參照與邏輯生命週期選型

本文件記錄 W-06 候選值模型的選型與量測結果，屬於[ADR-10](README.md)「Go GC 管實體記憶體，PHP 邏輯生命週期獨立」的實作基準。它不是 PHP 引擎完成或產品驗收的證明。對應 REQ-007、REQ-015、REQ-016、REQ-017、REQ-020；REQ-023 尚未涵蓋。

## 選定做法

| 項目 | 選定做法 | 未採用的選項與理由 |
|---|---|---|
| 值表示 | 單一 `value` 結構分開保存未定義、null、bool、int、float、位元組字串、array、object 與參照 | Go `any` 會混用 Go 預設轉型，也無法區分未定義與 null |
| 整數寬度 | 由請求 heap 的 32／64 位元 profile 決定範圍與陣列鍵上限 | 固定 int64 會讓 32 位元平台的鍵轉換與溢位結果錯誤 |
| 字串 | Go `string` 保存不可變位元組，進出時複製 | `[]byte` 共用會讓呼叫者改動已存的 PHP 字串 |
| 參照 | `reference` 是共享位置，每個綁定持有一份計數 | 以指標直接指向變數會在陣列成長或 unset 後失效 |
| array | 依插入順序的 bucket 指標陣列；連續整數鍵時免索引，其他形狀轉為 map 索引 | 只用 Go map 無法保留 PHP 順序；bucket 值陣列在成長後會使元素參照失效 |
| 複製 | 寫入時分離；唯一擁有者的參照元素複製成值，其他參照保持共享 | 一律深拷貝成本過高，一律共享參照會違反 PHP 8.5.12 行為 |
| 解構 | 以邏輯計數決定解構時機，解構期間暫時持有物件，結束後無人持有才釋放 | Go finalizer 不保證時機與順序，不能產生 PHP 可觀察的輸出順序 |
| 循環 | 對可能的根做同步試算刪除；先跑一次解構，再重新判定是否被復活 | 只靠 Go GC 無法執行循環中的解構，也無法回報 `gc_collect_cycles` 數量 |
| 弱參照 | 物件記錄唯一 WeakReference 與所屬 WeakMap，釋放時清除並釋放 map 值 | 以 Go weak pointer 無法保證解構期間仍可取得目標 |
| 請求結束 | 先依符號表反向刪除只被變數持有的物件，再依建立順序執行其餘解構，最後關閉 heap | 直接丟棄 heap 會漏掉 PHP 規定的解構與輸出 |
| 輸出快照 | 深拷貝成 Go 擁有的資料，拒絕物件 handle 與遞迴陣列 | 回傳內部 value 會讓請求結束後仍可操作活物件 |

## 量測結果

在 Apple M3、Go 1.26.5 上以 `go test -run '^$' -bench . -benchtime 2000x -count 3 ./internal/runtime/` 量測，原始數據見[證據](../implementation/evidence/W-06-php85-lifecycle-linux-386.json)。

| 操作 | 每次耗時 | 配置 |
|---|---|---|
| 連續追加 1024 個整數 | 約 85～98 µs | 1040 次、約 128 KB |
| 複製 1024 元素陣列並寫入一格 | 約 67～71 µs | 1037 次、約 128 KB |
| 綁定參照並寫入 | 約 88～95 ns | 1 次、80 B |
| 建立並解構一個物件 | 約 152～164 ns | 2 次、144 B |
| 回收 100 個自我循環物件 | 約 131～199 µs | 642 次、約 96 KB |

每個元素一次配置是 bucket 指標帶來的主要成本。後續最佳化可改用分塊 bucket 或世代索引保留穩定位置，但必須以相同語意測試與量測結果比較後才能替換。

## 已知限制

- 只對 PHP 8.5.12 在模擬 linux/386 的參考結果驗證，早期世代、舊物件模型世代與其他平台仍缺差異案例。
- 浮點數、資源與複合值作為陣列鍵尚未模型化，會回報錯誤而不是猜測行為。
- 參照參數、參照回傳與型別化屬性的限制要等呼叫與類別模型存在後驗證。
- 緩衝池化（REQ-023）尚未實作；目前不重用任何請求資料。
- 同一次循環回收內多個解構的先後，Zend 取決於根緩衝區的槽位重用；本模型依加入緩衝的先後執行，兩者可能不同。
- heap 不支援並行使用，必須由單一 Execution 擁有。
