# W-01 產品契約與威脅檢查

本文件將[規格](../spec/specification.zh-TW.md#chapter-03)中的契約整理為實作與審查入口，不代表保護措施已實作或驗證。對應 REQ-001、REQ-077、REQ-078；產品驗收 T-001、T-002、T-153 至 T-156 仍須由各自的負責工作包執行。

## 入口與信任

| 入口 | 不可信輸入與必要檢查 | 資料與效果 |
|---|---|---|
| Go API | 呼叫者提供的 PHP、值與設定仍需驗證；宿主 callback 是受信任的宿主程式 | 回傳獨立快照；callback 不保證可強制中斷 |
| CLI | 程式、參數、環境及檔案內容按所選 profile 與能力檢查 | 輸出、退出狀態及檔案效果依 CLI 契約記錄 |
| FastCGI | Web 伺服器傳來的參數、body、上傳與中止事件都需限量及驗證 | 保留原始請求語意；已送出的回應不能撤回 |
| HTTP | 路由、標頭、body、上傳及外部輸入需限量及驗證 | 不得將 PHP 原始碼當靜態檔案洩漏 |
| 封裝執行檔 | manifest、程式映像及動態載入需驗證版本、完整性與能力 | 程式映像及可寫資料分開；未知動態程式按部署政策處理 |

所有入口都建立請求範圍的精確 release／platform profile、政策與配額，經共用語意、能力及受控資源路徑執行。已驗證的不可變 Program 可共用，Execution 的可變值、環境、Session 視圖和錯誤狀態不可共用。共享服務只能透過明確授權的介面存取。

資料流由入口經有界接納、初始化、解析與驗證，進入 VM 或經驗證的 native 後端，再透過共同的能力介面存取檔案、資料庫、網路、程序、callback 和共享服務。輸出、診斷與清理結果屬於當次請求。預設不授權啟動系統指令，直接參數與 shell 字串是不同能力。

受信任應用面對惡意外部輸入是一般網站模型。受限制的第三方 PHP 在同程序執行時只有語言層限制，不能宣稱作業系統隔離。惡意 PHP 或原生元件需要受限獨立程序。宿主 Go 程式、作業系統帳號、資料庫管理員與簽章權限不屬於此模型中 PHP 攻擊者控制的範圍。

## 不變條件檢查

下表是審查清單，原文以[規格第 3 章](../spec/specification.zh-TW.md#chapter-03)為準。各項測試須在相應元件存在後執行，目前不代表通過。

| 條件 | 審查時確認 |
|---|---|
| I-01 | 請求可變值、設定、符號、錯誤及資源識別不被其他請求直接存取。 |
| I-02 | 跨請求交換只經明確註冊的共享服務，且不繞過其鎖定與權限。 |
| I-03 | PHP 無法取得任意 Go 指標、反射權限、程序環境修改權或原生函式位址。 |
| I-04 | 所有後端、最佳化、快取命中及 callback 使用相同的資源能力檢查。 |
| I-05 | 相同 profile、能力、輸入及可控環境下，各後端的可觀察結果相容。 |
| I-06 | 共用程式只存定義與範本，static、動態宣告及請求快取不放入共用物件。 |
| I-07 | 只清理當前請求已完成初始化且持有的資源，半初始化狀態不可執行。 |
| I-08 | PHP 錯誤、exit、例外及政策拒絕不終止宿主程序。 |
| I-09 | 回傳資料不指向可由後續請求覆寫的記憶體或已釋放資源。 |
| I-10 | 支援聲明可追溯需求、工作包、驗收測試與實際證據。 |
| I-11 | 未支援、未測試、政策拒絕、允許差異及實作失敗分別記錄。 |
| I-12 | 聲稱不受特定 CVE 影響前，分析受影響路徑、依賴及回歸測試。 |

## 威脅與驗證責任

| 威脅或故障 | 必須維持的條件 | 後續驗證 |
|---|---|---|
| 請求互相污染或讀取失效資源 | 請求持有可變狀態；結果獨立；資源只由擁有者清理一次 | W-05、W-22 的交錯與故障測試 |
| 路徑穿越、符號連結替換、網路重導或 DNS 變化 | 每次資源操作經能力檢查；檔案與實際連線目的地均須驗證 | W-20、W-32 的負面測試 |
| 最佳化、快取、動態程式或 native 繞過檢查 | profile、能力與取消檢查在所有後端保留；快取只含驗證過的不可變資料 | W-15、W-18、W-23、W-38 的差異測試 |
| 惡意或損毀程式映像、過大輸入 | 解碼與驗證有界，拒絕無效資料及溢位 | W-09、W-16 的模糊與邊界測試 |
| 配額失敗、取消、外部服務或清理失敗 | 不執行半初始化狀態；保留失敗分類與已提交效果；只清理已取得資源 | W-05、W-14、W-41 的故障注入 |
| 惡意 PHP、原生元件或不合作 callback | 同程序 goroutine 不是硬性沙箱；硬性停止與不可信程式需要受限獨立程序 | W-41、W-46 的程序隔離測試 |

`compat`、`observe`、`enforce` 均不得關閉格式驗證、請求隔離、能力範圍或宿主資源上限。來源追蹤不能取代應用程式的授權與商業規則。詳細規則與例外以[第 10 至 11 章](../spec/specification.zh-TW.md#chapter-10)為準。

## 決策與授權

[決策登錄](README.md)區分使用者已確認方向、本版設計基準、實驗閘門及已取代決策。內部演算法與私有布局可在不變條件內調整，重大設計須記錄理由、替代方案、證據與影響。

本次已授權實作、推送並在 CI 通過後合併與清理已合併分支。正式軟體 release、正式環境或權限變更、付費、破壞性資料操作及縮減相容或安全承諾仍需個別授權。歷史參考引擎與不安全測試使用隔離環境及測試資料，付款、郵件與外部效果使用替身或獲授權 sandbox。

規格中的保護和入口目前是要求，不是已驗證功能。來源鎖、可執行引擎、歷史相容、競品測量與真實應用驗收均待後續工作證明。
