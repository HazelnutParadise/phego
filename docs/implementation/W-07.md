# W-07｜維護者可以在受控 ABI 下驗證 LLVM 與 Go 橋接

規格工作包：LLVM與Go橋接概念驗證。階段：M1。負責角色：Native後端維護者。

實作狀態：數值、callback 與合作式取消已有局部探查。驗收狀態：`not_run`。本 draft 沒有可執行 PHP 引擎。

來源：[規格1.1.2](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/spec/specification.zh-TW.md)、[工作包原始記錄](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/data/phego-work-packages.json)、[需求](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/data/phego-requirements.json)、[驗收情境](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/data/phego-acceptance-tests.json)。

## 交付行為與實作順序

1. 以固定ABI連結小型native區段。
2. 驗證數值、opaque handle、callback、例外狀態、取消與GC壓力。
3. 至少在Linux amd64／arm64驗證連結與依賴。

交付物：可重現橋接實驗、ABI風險報告、可行平台清單。

## 局部數值橋接探查

`experiments/nativeabi/xor.ll` 定義固定寬度數值運算，`experiments/nativeabi/main.go` 以 cgo 呼叫原生函式並核對五組輸入。XOR 的左右參數交換不影響結果，因此此探查無法偵測參數次序錯誤。此探查對應 REQ-052、REQ-053 的早期部分證據，不是 PHP 執行或整票驗收。

在 macOS arm64、Apple Clang 21 與 Go 1.26.5 環境執行下列命令，五組通過。將原生運算刻意換成 OR 時，程式拒絕錯誤結果；[CI 探查](../../.github/workflows/native-probe.yml)也包含此反例，使用的是執行器提供的工具鏈。編譯器與 linker 提示目標三元組覆寫及重複 library；此結果不能代表 W-02 固定的 LLVM 23.1.4 或 Linux 結果。

```sh
probe_dir=$(mktemp -d -t phego-native-abi)
clang -c experiments/nativeabi/xor.ll -o "$probe_dir/probe.o"
ar rcs "$probe_dir/libphegoprobe.a" "$probe_dir/probe.o"
CGO_ENABLED=1 CC=clang CGO_LDFLAGS="-L$probe_dir -lphegoprobe" go run -tags=phego_native_probe ./experiments/nativeabi
```

在無網路、非 root、唯讀根目錄且資源受限的 Linux arm64 容器，使用 W-02 鎖定的 LLVM 23.1.4 與 Go 1.27.3，五組數值案例通過；Linux amd64 在模擬環境也通過相同案例。封存檔雜湊與 W-02 鎖定值相符，編譯器提示目標三元組覆寫。[原始命令、輸出與限制](evidence/W-07-numeric-linux.json)保留於專案；arm64 命令尚無執行時間上限，amd64 命令已有 600 秒上限；兩者都未驗證中斷後清理，也尚未提供完整重跑入口，不能將此觀察當成完整驗收。

這需要明確啟用 build tag、cgo 與原生編譯器；預設 `CGO_ENABLED=0 go test ./...` 不依賴此探查。產品請求的受限 handle、callback、例外、取消與 GC 壓力均尚未驗證，不得宣稱 native 後端已可使用。

## 局部 native-to-Go callback 探查

`experiments/nativecallback/invoke.ll` 經原生程式回呼 Go；實驗登錄表用固定寬度 owner 與 token 檢查呼叫、釋放及錯誤狀態，Go panic 轉為狀態碼。這是獨立測試登錄表，沒有接入產品請求生命週期；識別值可以猜測，不能隔離不可信 native 程式。

macOS arm64、Linux arm64 與模擬 Linux amd64 各通過 10 項測試及 race 檢查。Linux 使用 W-02 鎖定版本的 LLVM 與 Go；[Linux 命令、輸出節錄與限制](evidence/W-07-callback-linux.json)及 [macOS 紀錄](evidence/W-07-callback-macos.json)記錄平台與來源。[callback CI](../../.github/workflows/native-callback.yml) 定義使用執行器提供的 Clang，並依 `go.mod` 設定 Go，也包含原生程式跳過回呼的反例；遠端結果尚未確認。以下命令在專案根目錄執行，使用宿主提供的 Clang 與 Go；Linux 鎖版工具鏈的既往命令與限制見 Linux 紀錄，完整重跑入口尚未提供。

```sh
probe_dir=$(mktemp -d)
clang -c experiments/nativecallback/invoke.ll -o "$probe_dir/invoke.o"
ar rcs "$probe_dir/libphegocallback.a" "$probe_dir/invoke.o"
CGO_ENABLED=1 CC=clang CGO_LDFLAGS="-L$probe_dir -lphegocallback" go test -race -count=1 -tags=phego_native_probe ./experiments/nativecallback
```

測試包含單次 GC、token 耗盡與同時啟動的呼叫／釋放，但沒有強制回呼執行中與釋放交錯，也不代表複雜 Go 值的保活或 GC 壓力已通過。呼叫計數器尚未處理整數溢位；native 建立執行緒、重入、取消、PHP 例外及完整 ABI 仍未驗證。

## 局部原生取消探查

`experiments/nativecancel/loop.ll` 在原生迴圈每次反覆呼叫 Go，檢查合作式取消。Go 登錄表只以固定寬度 token 跨 ABI；狀態 0 代表完成，1 代表取消，2 代表 token 無效或已釋放，3 代表 Go 檢查點 panic。此探查對應 REQ-052、REQ-053 的局部證據，不是產品請求的取消實作。

在 macOS arm64 使用 Apple Clang 21、Go 1.26.5，11 項測試通過 race 檢查；特殊設定 `GODEBUG=panicnil=1` 下的 panic 測試也通過。[本機命令與紀錄](evidence/W-07-cancel-macos.json)包含來源雜湊與限制。將原生程式替換成直接回報成功時，計數與無效 token 的測試均失敗。[CI 探查](../../.github/workflows/native-cancel.yml)包含上述測試和反例，使用執行器提供的 Clang 與 `go.mod` 指定的 Go 版本。

```sh
probe_dir=$(mktemp -d)
clang -O2 -c experiments/nativecancel/loop.ll -o "$probe_dir/loop.o"
ar rcs "$probe_dir/libphegocancel.a" "$probe_dir/loop.o"
CGO_ENABLED=1 CC=clang CGO_LDFLAGS="-L$probe_dir -lphegocancel" go test -race -count=1 -tags=phego_native_probe ./experiments/nativecancel
GODEBUG=panicnil=1 CGO_ENABLED=1 CC=clang CGO_LDFLAGS="-L$probe_dir -lphegocancel" go test -count=1 -tags=phego_native_probe -run '^TestNilPanicCannotBeReportedAsSuccess$' ./experiments/nativecancel
```

Linux arm64 與模擬 Linux amd64 使用 LLVM 23.1.4、Go 1.27.3，在受限容器各通過 11 項 race 測試；[命令、來源雜湊與限制](evidence/W-07-cancel-linux.json)記錄本次結果。紀錄使用原執行環境的暫存路徑，不能保證原樣重跑，中斷後清理也尚未驗證。

這個實驗沒有接入產品請求生命週期，也不是安全隔離或強制中止。宿主自訂的 `Context.Err()` 若永久阻塞，原生呼叫無法靠此探查強制停止。釋放 token 只使其失效，不等待正在執行的宿主檢查；檢查返回後回報狀態 2。零次迴圈不執行取消檢查。單次 GC 測試不證明複雜值保活或 GC 壓力；token 可猜測，不可作為不可信原生程式的隔離機制。

## 局部 handle 探查

`experiments/nativehandle/sum.ll` 只持有固定寬度的 owner 與 handle，經 Go 存取函式逐項讀取 Go 表格中的值。handle 由槽位與代次組成，釋放後重用槽位會讓舊 handle 失效，代次用盡的槽位直接退役。加權總和讓元素次序錯誤可被偵測；存取函式可回報例外狀態（2）與被攔截的 Go panic（3），原生端不寫入結果。對應 REQ-052、REQ-053 的局部證據，不是產品 ABI。

macOS arm64（Apple Clang 21、Go 1.26.5）與 Linux arm64（W-02 鎖定的 LLVM 23.1.4、Go 1.27.3，受限容器）各通過 9 項 race 測試，並在 `GOEXPERIMENT=cgocheck2` 下通過；包含 GC 壓力下並行讀取與並行釋放。[Linux 輸出](evidence/W-07-handle-linux-arm64.log)已保存，[CI 探查](../../.github/workflows/native-handle.yml)另含忽略狀態的原生反例。Linux amd64 尚未以鎖定工具鏈執行本探查；表格以單一鎖保護，未量測效能，也不是不可信原生程式的隔離機制。

## 本 draft 與後續實作的檢查

- 文件與追蹤驗證入口：`python3 tools/validate_docs.py`、`python3 -m unittest discover -s tools -p 'test_*.py'`。文件通過不構成上述 PHP 情境通過。

- 有 Go 模組後，實作交付須執行 `gofmt` 檢查、`CGO_ENABLED=0 go test ./...`、`go vet ./...`。並行變更新增 `go test -race ./...`，race 需要的建置工具與預設 Pure-Go 核心依賴分開。

- 格式解析與驗證器加入 fuzz 回歸；完整 native ABI／指標／GC 壓力與後端差異，以及 Web 與網站的真實渲染及互動測試入口仍待實作。

- Ready for review 前提交實際程式、測試位置、命令、commit、環境、原始結果、相容與安全差異，以及所有未涵蓋條件。只合併這份計畫不能關閉實作 issue。

## 相容、安全與範圍

維持 Go 單函式嵌入、預設不依賴 cgo／LLVM、第一版 PHP 起的全部歷史範圍、有界 goroutine、請求隔離與 Apache／Nginx FastCGI。任何後端都保留能力檢查及取消語意，正式執行不回退 Zend。
