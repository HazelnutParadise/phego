# W-41｜維護者可以重現並修正格式、並行與故障注入缺陷

規格工作包：全系統fuzz、race與故障注入。階段：M7。負責角色：安全測試維護者。

實作狀態：`not_started`。驗收狀態：`not_run`。本 draft 目前只提交實作計畫，沒有可執行 PHP 引擎。

來源：[規格1.1.2](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/spec/specification.zh-TW.md)、[工作包原始記錄](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/data/phego-work-packages.json)、[需求](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/data/phego-requirements.json)、[驗收情境](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/data/phego-acceptance-tests.json)。

## 交付行為與實作順序

1. 覆蓋高風險parser、decoder、資源與交錯。
2. 建立受控CVE回歸性質測試。
3. 加入native檢查與長操作超限，保存最小重現案例。

交付物：fuzz corpus、race／故障報告、安全回歸清單。

## 前置條件與整合

規格依賴：W-05、W-16、W-17、W-22、W-25、W-27、W-28、W-30。

- 整票整合另需 W-46：程序隔離終止與硬性限制測試需要真實 worker。
- 整票整合另需 W-38：完整 native ABI／指標與 GC 檢查需要正式原生 Runtime。

安全回歸需從原始公告重新查證適用元件及觸發條件。CVE 編號出現在規格裡不等於已驗證。native 相關檢查在 W-39 接上實際後端再執行，不能以未建置當通過。

## 預定實作與測試位置

tests/security/、tests/fuzz/、tests/concurrency/。這些是待建立的位置，實際布局可在規格內調整，交付時須填寫真實檔案與行號。

## 輸入、狀態與失敗處理

輸入由入口驗證精確 release／platform profile、build profile、能力及資源上限。只有完成驗證的不可變產物可共用。可變值、錯誤與清理紀錄由當次操作或 Execution 擁有。

| 情境 | 處理與可觀察結果 | 驗證責任 |
|---|---|---|
| 正常輸入 | 依下列需求產生輸出、診斷與可比較副作用 | 本票實作與局部回歸 |
| null／缺少必要欄位 | 依該版本區分合法 null、缺參數與無效設定，回報具位置的錯誤 | 本票輸入邊界測試 |
| 空字串／空集合／零 | 分開驗證有效空輸入、零值與不合法上限，不能以通用空值判斷合併 | 本票輸入邊界測試 |
| 來源或外部服務失敗 | 保留來源缺失、外部錯誤、政策拒絕及未知分類，不能固定回傳成功 | 本票故障注入 |
| 重複／並行／重入 | 可共用的產物維持唯讀，拒絕跨請求活物件與失效 handle | 本票交錯與重入回歸 |
| 取消／部分成功／清理失敗 | 終止受控工作，只清理已取得的資源，記錄已提交副作用與不可中斷部分 | 本票中斷與清理回歸 |

每列由本票擁有局部行為測試；下列情境的最終驗收負責票負責完整整合，不重複宣稱同一證據已完成。與該票輸入不相容的列須在實作審查中附不適用理由。

## 需求與完成條件

- **REQ-010 PHP 與模板解析**：PHP 開發者可以執行含混合 HTML、字串插值與支援版本語法的原始檔。
  完成條件：解析與錯誤位置符合 profile，輸入限制在配置前生效。

- **REQ-017 有序陣列**：PHP 開發者可以使用保持 PHP 鍵轉換與順序的 array。
  完成條件：packed／ordered 表示轉換前後，索引、順序與引用結果一致。

- **REQ-021 循環與弱參照**：PHP 開發者可以使用 gc 系列、WeakReference 與 WeakMap。
  完成條件：循環、弱鍵與值指回鍵的行為對照基準，不永久強參照。

- **REQ-022 初始化安全**：平台管理者可以在任何初始化步驟失敗時維持服務完整性。
  完成條件：只有已提交資源進入清理，下一請求不取得半成品。

- **REQ-025 驗證 Bytecode**：平台管理者可以安全拒絕損毀或不相容的中介程式。
  完成條件：載入前驗證長度、索引、控制流程、frame 與能力，資源消耗有界。

- **REQ-026 可取消 VM**：平台管理者可以中止高成本 PHP 執行且釋放核心資源。
  完成條件：回邊、配置、函式與長操作有檢查點，錯誤可分類。

- **REQ-027 Fiber 與 Generator**：PHP 開發者可以依 PHP 的暫停／恢復語意執行程式。
  完成條件：同一 Execution 的狀態不被多個 Fiber 任意平行修改。

- **REQ-028 Goroutine 請求模型**：網站管理者可以同時執行多個獨立 PHP 請求。
  完成條件：不同請求共享程式但不共享可變執行狀態。

- **REQ-031 資源預算**：平台管理者可以限制運算、邏輯記憶體、輸出與外部資源。
  完成條件：超限在可控邊界拒絕，不把邏輯額度誤稱為 RSS 硬限制。

- **REQ-032 高風險程序隔離**：平台管理者可以對需要硬性停止或較低信任的程式選用隔離 worker。
  完成條件：worker 受到 OS 權限與資源限制，崩潰不終止控制程序。

- **REQ-037 路徑與 SSRF**：網站管理者可以防止 PHP 超出授權檔案與網路範圍。
  完成條件：實際使用時檢查根目錄、解析IP、重新導向與代理。

- **REQ-038 FastCGI 協定**：網站管理者可以以 Apache／Nginx 連接 Phego Responder。
  完成條件：合法 record、串流、重用、abort 與協定錯誤有互通測試。

- **REQ-040 標頭與輸出**：PHP 開發者可以輸出狀態、Cookie、二進位內容與緩衝資料。
  完成條件：重複Set-Cookie與標頭替換符合PHP語意，stdout與stderr不混淆。

- **REQ-041 安全靜態與入口**：網站管理者可以使用內建HTTP服務或保留現有Web路由。
  完成條件：只公開document-root及明確入口，PHP執行失敗不回傳原始碼。

- **REQ-042 表單與上傳**：PHP 開發者可以使用相容的表單、Cookie與檔案上傳資料。
  完成條件：鍵轉換、重複欄位、深度、大小、暫存登錄及move_uploaded_file正確。

- **REQ-043 Session 互斥與寫回**：PHP 開發者可以安全共享同一session ID的資料。
  完成條件：同ID採對應後端的鎖定契約，不同站台不混用鍵。

- **REQ-044 格式與進度安全**：網站管理者可以使用經認證的序列化與upload progress能力。
  完成條件：格式切換不誤讀半初始化資料，能力未完成不回報支援。

- **REQ-045 提早結束回應**：PHP 開發者可以使用fastcgi_finish_request後完成允許的後續工作。
  完成條件：回應關閉與Execution結束分開，名額、鎖與額度持續有效。

- **REQ-048 字串與PCRE**：PHP 開發者可以執行符合PHP語意的字串、編碼與正規表示式操作。
  完成條件：PCRE能力不以RE2子集冒充，錯誤與限制可查詢。

- **REQ-050 外部函式庫**：PHP 開發者可以使用明列的HTTP、crypto、XML、壓縮、影像與國際化能力。
  完成條件：按函式族認證，依賴版本與純Go／native性質如實公開。

- **REQ-053 受控ABI**：維護者可以以穩定資料契約連接原生程式與Go Runtime。
  完成條件：不私藏Go指標，handle的擁有者、代次與保活經檢查。

- **REQ-062 唯讀與有界**：平台管理者可以共享程式快取但不共享請求資料。
  完成條件：快取有上限，逐出不影響活躍Program，請求狀態不進入快取。

- **REQ-063 編譯合併與取消**：平台管理者可以避免相同來源的編譯風暴。
  完成條件：同鍵共享編譯，單一等待者取消不殺掉其他需求。

- **REQ-064 磁碟快取安全**：平台管理者可以從可信來源恢復快取並拒絕損毀資料。
  完成條件：格式驗證、摘要、來源信任與native簽章政策各自成立。

- **REQ-067 安全影響判斷**：維護者可以以證據判定官方PHP或依賴漏洞是否影響Phego。
  完成條件：分析對應功能、依賴與測試，不只看語言或CVE名稱。

- **REQ-068 設定重載**：網站管理者可以安全替換站台設定而不混用請求狀態。
  完成條件：新代次原子發布，失敗保留舊設定，強制取消模式明確。

- **REQ-073 模糊與故障測試**：審查者可以檢查惡意輸入與中途失敗的系統完整性。
  完成條件：高風險parser／decoder有fuzz corpus，各初始化步驟有故障注入。

- **REQ-075 長時間與並行證據**：審查者可以驗證持續服務不累積無界資源。
  完成條件：滿足文件所定24小時及100萬請求基準並分析保留趨勢。
