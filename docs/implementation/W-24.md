# W-24｜Go 開發者可以執行檔案、重用程式並註冊受控 callback

規格工作包：正式SDK與HostCall。階段：M4。負責角色：SDK維護者。

實作狀態：`not_started`。驗收狀態：`not_run`。本 draft 目前只提交實作計畫，沒有可執行 PHP 引擎。

來源：[規格1.1.2](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/spec/specification.zh-TW.md)、[工作包原始記錄](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/data/phego-work-packages.json)、[需求](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/data/phego-requirements.json)、[驗收情境](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/data/phego-acceptance-tests.json)。

## 交付行為與實作順序

1. 完成Run／Compile／RunFile／Close與型別轉換。
2. 實作輸出快照、錯誤及受限HostContext。
3. 加入callback重入、panic、取消與並行範例。

交付物：公開SDK、可編譯範例、SDK測試。

## 前置條件與整合

規格依賴：W-08、W-17、W-20、W-22。

依規格依賴即可開始；各子能力的適用平台與來源鎖必須明示。

先驗證這張票的局部交付，再把證據交給對應的完整產品驗收負責票。依賴未完成時可準備 fixture 與預期結果，不能宣稱已通過產品情境。

## 預定實作與測試位置

儲存庫根目錄 Go SDK、api/、examples/、tests/sdk/。這些是待建立的位置，實際布局可在規格內調整，交付時須填寫真實檔案與行號。

## 輸入、狀態與失敗處理

輸入由入口驗證精確 release／platform profile、build profile、能力及資源上限。只有完成驗證的不可變產物可共用。可變值、錯誤與清理紀錄由當次操作或 Execution 擁有。

| 情境 | 處理與可觀察結果 | 驗證責任 |
|---|---|---|
| 正常輸入 | 依下列需求產生輸出、診斷與可比較副作用 | 本票實作與局部回歸 |
| null／缺少必要欄位 | 依該版本區分合法 null、缺參數與無效設定，回報具位置的錯誤 | 本票輸入邊界測試 |
| 空字串／空集合／零 | 分開驗證有效空輸入、零值與不合法上限，不能以通用空值判斷合併 | 本票輸入邊界測試 |
| 來源或外部服務失敗 | 保留來源缺失、外部錯誤、政策拒絕及未知分類，不能固定回傳成功 | 本票故障注入 |
| 重複／並行／重入 | 可共用的產物維持唯讀，拒絕跨請求活物件與失效 handle | 本票交錯與重入回歸 |
| 取消／部分成功／清理失敗 | 終止受控工作，只清理已取得的資源，記錄已提交副作用與不可中斷部分 | 本票中斷與清理回歸 |

每列由本票擁有局部行為測試；下列情境的最終驗收負責票負責完整整合，不重複宣稱同一證據已完成。與該票輸入不相容的列須在實作審查中附不適用理由。

## 需求與完成條件

- **REQ-005 單函式執行**：Go 開發者可以透過 phego.Run 執行 PHP 字串並取得結果。
  完成條件：一般輸出、return、PHP 錯誤與 exit 皆有明確結果，不終止宿主。

- **REQ-006 重用編譯結果**：Go 開發者可以共用 Program 並從不同 goroutine 同時執行。
  完成條件：Program 不可變，各 Run 的輸出、static 與變數不互相影響。

- **REQ-007 資料傳遞與擁有權**：Go 開發者可以傳入明確型別資料並在請求結束後安全讀取輸出快照。
  完成條件：位元組字串、有序鍵、數字範圍與複製行為有測試，無失效活物件外流。

- **REQ-008 宿主函式註冊**：Go 開發者可以明確授權 PHP 呼叫特定 Go 函式。
  完成條件：簽章、權限、來源標記、重入與取消規則在註冊時驗證。

- **REQ-009 關閉與取消**：Go 開發者可以取消執行或有期限地關閉 Engine。
  完成條件：停止接納、取消與 drain 可觀察，已開始的輸出與副作用不被隱藏。

- **REQ-030 請求環境隔離**：PHP 開發者可以在自己的執行範圍設定目錄、環境、INI 與時區。
  完成條件：宿主程序與其他請求不受其變更影響。

- **REQ-033 能力式 I/O**：平台管理者可以只授權 PHP 使用明確的檔案、網路、資料庫與宿主功能。
  完成條件：所有入口與後端經過同一能力檢查。

- **REQ-034 來源追蹤**：平台管理者可以追蹤外部資料進入高風險操作的路徑。
  完成條件：字串區段、複雜值、參照、最佳化與宿主回傳保留必要來源。

## 本 draft 與後續實作的檢查

- 本輪只做文件與追蹤驗證：`python3 tools/validate_docs.py`、`python3 -m unittest discover -s tools -p 'test_*.py'`。文件通過不構成上述 PHP 情境通過。

- 有 Go 模組後，實作交付須執行 `gofmt` 檢查、`CGO_ENABLED=0 go test ./...`、`go vet ./...`。並行變更新增 `go test -race ./...`，race 需要的建置工具與預設 Pure-Go 核心依賴分開。

- 格式解析與驗證器加入 fuzz 回歸；native 加入實際 ABI／指標／GC 壓力與後端差異；Web 與網站加入真實渲染及互動。這些命令及測試入口尚待實作，沒有宣稱本輪執行。
