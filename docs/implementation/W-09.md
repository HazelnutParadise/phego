## Lexer

`internal/frontend/lexer.go` 依 PHP 8.5.12 規則把原始檔切成 token，`token.go` 定義與 `token_get_all()` 相同名稱的 token 種類。整數寬度與 `short_open_tag` 由呼叫者的 profile 指定；輸入上限在配置 token 前檢查，token 數另有上限。每個位元組恰好屬於一個 token，未結束的註解與字串回報含行號的診斷，不會 panic。內部採 Go 的狀態堆疊設計，對外只保證 token 結果與 PHP 相同。

`tools/frontend_corpus.py` 從鎖定的 php-src 封存檔取出 Zend 與 tokenizer 測試的 5449 段 `--FILE--` 原始碼；這些是 PHP 授權的測試資料，只在專案外產生。以 `tests/frontend/token_dump.php` 在 32 位元固定映像與原生 arm64 自建的 64 位元 PHP 8.5.12 取得參考 token，Phego 在兩種寬度下 5449 個檔案的每個 token 名稱、文字與起始行全部一致；90 秒 fuzz 執行約 2000 萬次無失敗。[命令、雜湊與限制](evidence/W-09-lexer-differential-20261031.json)已記錄。

局部測試位於 `internal/frontend/lexer_test.go`，差異比對位於 `lexer_corpus_test.go`（設定 `PHEGO_LEXER_CORPUS` 才執行）。Parser、AST、來源映射、語法範圍清單與錯誤恢復尚未實作，因此本票退出條件仍未完成。

- 本輪只做文件與追蹤驗證：`python3 tools/validate_docs.py`、`python3 -m unittest discover -s tools -p 'test_*.py'`。文件通過不構成上述 PHP 情境通過。

## 相容、安全與範圍

維持 Go 單函式嵌入、預設不依賴 cgo／LLVM、第一版 PHP 起的全部歷史範圍、有界 goroutine、請求隔離與 Apache／Nginx FastCGI。任何後端都保留能力檢查及取消語意，正式執行不回退 Zend。
