## 高階 IR

`ir.Lower` 接收 `frontend.Parse` 產生的語法樹和同一個 profile，回傳一個檔案的 `Unit`：檔案頂層程式、所有具名函式、類別宣告與編譯期警告。致命的編譯錯誤回傳 `*CompileError`，帶 PHP 回報的訊息與行號。`Unit` 在降低完成後就不再變動，也不保存任何請求狀態，所以同一個 profile 下可以給多個請求共用。

每個 PHP 操作在 IR 裡都還是自己的節點。讀屬性是 `prop`，因為它可能跑 `__get` 或 hook。字串串接是 `binary "."`，因為它可能呼叫 `__toString`。寫入陣列元素是帶寫入標記的 `dim`，因為 `ArrayAccess` 物件會呼叫 `offsetSet`。IR 不把這些操作換成記憶體存取，型別推論與最佳化要等後續工作包，而且必須依效果判斷能不能動它。

名稱依 PHP 的規則在編譯時解析。類別名稱套用 `use` 與目前命名空間，`self`、`parent`、`static` 留到執行時決定。命名空間裡未限定的函式與常數名稱記下兩個候選，例如 `App\strlen` 找不到時改用 `strlen`。`true`、`false`、`null` 直接變成字面值。

每個函式有自己的變數表，記錄參數、`global`、`static`、closure 捕捉、參照綁定，以及傳給「可能以參照接收」參數的情形。呼叫端在編譯時不知道對方的參數是不是參照，所以傳入的變數都標成可能被別名，最佳化不能把它換成暫存值。用到 `$$name`、`extract()`、`compact()`、`include` 或 `eval` 的函式標成動態作用域。箭頭函式的捕捉清單依 PHP 的 `find_implicit_binds` 規則建立，包含巢狀箭頭函式的本體與巢狀 closure 的 `use` 清單。

呼叫的每個參數記下是否具名、是否展開，以及是否可能以參照傳遞。函式記下所屬檔案的 `strict_types`，呼叫端的嚴格模式決定參數轉型。型別依 `ReflectionType` 的寫法正規化，例如宣告 `int|string|null` 會寫成 `string|int|null`，`iterable` 單獨使用時保留 `iterable`。

每個節點帶一組可能的效果：警告、例外、執行使用者程式、輸出、結束、寫入、建立參照、動態作用域、編譯新程式碼、暫停與外部執行。效果採保守估計，沒有標記才是保證。運算元是字面值時才收窄，例如 `1 + 2` 沒有效果，`1 / 0` 可能丟出例外，`$a . $b` 可能呼叫 `__toString`。覆寫變數時舊值可能被解構，所以指定運算一律可能執行使用者程式。

## 與 PHP 的對照

三組對照都以固定映像 `php@sha256:add6a138…`（arm64）產生參考，`35fd7ee3…`（amd64）產生的輸出逐位元組相同。[命令、雜湊與限制](evidence/W-11-hir-differential-20261101.json)已記錄。

**編譯錯誤與警告。** `tests/semantics/w11-hir/compile_dump.php` 對 W-09 使用的 5449 段 php-src 測試原始碼逐一執行 `php -l`，記錄 PHP 編譯時回報的錯誤與警告。前端接受且 PHP 沒有語法錯誤的 5307 個檔案中，PHP 能編譯的檔案 Phego 全部接受。657 個編譯錯誤中，337 個由降低程序以相同訊息與行號回報。48 個有編譯警告或棄用通知的檔案中，40 個的訊息、層級、行號與順序完全相同。其餘 320 個錯誤與 8 個警告檔屬於後續工作包，`internal/ir/corpus_gaps_test.go` 逐項歸類：316 個是類別成員、繼承、enum、hook 與 magic method 的檢查（W-13），5 個在 attribute 參數裡（W-13），5 個需要內建函式表（W-29，例如 `strlen()` 的結果不能寫入），2 個需要編譯期常數摺疊（W-15）。數量改變測試就失敗。這組對照由 `TestLowerMatchesCompileReference` 執行，設定 `PHEGO_LEXER_CORPUS` 才會跑。

**Reflection。** `tests/semantics/w11-hir/reflect.php` 載入 fixture 後以 Reflection 輸出函式、方法與 closure 的名稱、參數（型別、參照、可變長度、是否可省略、有無預設值、是否為建構式升級屬性）、回傳型別、是否回傳參照、是否為 generator、靜態變數與捕捉變數，以及在編譯時就決定的值（`X::class`、魔術常數與各種數字、字串、heredoc 字面值）。`TestLowerMatchesReflection` 從 IR 產生同樣的 JSON，三個 fixture 全部一致。比對時找到並修正了 `0b`、`0o` 開頭的超大數字：PHP 以 `value * 2 + c - '0'` 累加，加上字元碼與減去 `'0'` 各捨入一次。

**效果。** `tests/semantics/w11-hir/effects/magic.php` 的每一行是一個包在 `try` 裡的敘述，涵蓋 magic method、`ArrayAccess`、解構、autoload、迭代器、未定義變數、算術錯誤與 `match`。`effects.php` 在 PHP 執行它，記錄每行實際發生的使用者程式呼叫、警告與例外。`TestEffectsCoverObservedBehaviour` 檢查 IR 對每一行都宣告了 PHP 實際發生的效果，任何遺漏都會讓最佳化有機會刪掉或移動可觀察的行為。

`FuzzLower` 對前端接受的任意輸入檢查降低不會 panic，錯誤一定帶行號，60 秒約 1170 萬次沒有失敗。單元測試涵蓋名稱解析、別名標記、動態作用域、`strict_types`、函式提前宣告、整數寬度與編譯錯誤行號，預期值都先在 PHP 8.5.12 確認過。

## 尚未完成

- 只有 PHP 8.5.12。其他版本的語法與編譯規則尚未建模。編譯錯誤對照只用 64 位元 profile 跑過。
- 類別成員、繼承、enum、hook、magic method 與 attribute 的編譯期檢查（上述 321 項）由 W-13 負責，IR 目前只記錄宣告與程式碼。
- 編譯器不認得內建函式，也不會把呼叫綁定到同一檔案先前宣告的函式，所以 `strlen()` 的特殊編譯、`Cannot redeclare function strlen()` 以及「已知對方以值接收時 `f($a[])` 是錯誤」都還沒有處理（W-29）。
- 常數摺疊只做到字面值與 `true`／`false`／`null`。`(1+1)::class` 這類需要先計算運算子的錯誤，以及 PHP 在編譯時摺疊常數陣列而發出的警告，要等 W-15。
- `declare(encoding=...)` 前面若只有空敘述，PHP 會拒絕，但前端不保留空敘述，目前會接受。
- 效果是保守估計，還沒有型別推論，大多數涉及變數的操作都標成可能執行使用者程式。實際執行與 callback 次數的對照屬於 W-17 與 W-39。
