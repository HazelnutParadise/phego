# W-14｜Go 宿主可以區分 PHP 結束原因並正確清理請求

規格工作包：Frame、錯誤與shutdown。階段：M2。負責角色：執行引擎維護者。

實作狀態：已加入請求內的 frame、結束原因與收尾核心，尚未接通 PHP 執行入口。產品驗收狀態維持 `not_run`，本票不因局部重播通過而關閉。

來源：[規格1.1.2](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/spec/specification.zh-TW.md)、[工作包原始記錄](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/data/phego-work-packages.json)、[需求](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/data/phego-requirements.json)、[驗收情境](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/data/phego-acceptance-tests.json)。

## 交付行為與實作順序

1. 實作frame、exception、warning、exit與輸出。
2. 固定各種結束原因的PHP與Runtime收尾行為。
3. 加入部分輸出、收尾失敗與重入測試。

交付物：執行frame、錯誤分類、清理策略。

參考引擎固定為 `php@sha256:add6a138b6bd07edd645088917c081579f6e0d52d3c4361aff9d9309e6ebf9d9`，實測 profile 為 PHP 8.5.12、Linux arm64、64 位元整數、CLI、`php -n`。容器使用唯讀掛載、非 root、無網路、移除 capabilities，並限制程序、記憶體、CPU 與執行時間。官方 PHP 只建立參考結果，不參與產品執行。

固定的差異包含：一般 fatal error 禁止當時既存物件再解構，之後新建物件仍可正常解構；未捕捉 Throwable 允許 shutdown 與解構。shutdown 內 exit 可改退出碼，但不解除先前 fatal 對既存物件的標記。函式內物件依變數順序釋放，第一個解構拋例外後仍完成其餘局部值的 unwind。最內層輸出 handler 拋例外會停止剩餘 flush。handler 內的 echo 會被丟棄並產生棄用診斷。輸出 handler 執行時 heap 仍可用，handler 留存到最後的物件不再得到第二輪 shutdown 解構。

管理者取消、輸出 writer 失敗及內部錯誤會停止後續 PHP callback，保留已接受的輸出，只執行 Runtime 清理。這是宿主停止契約，不冒充 PHP 正常 shutdown。writer 接受位元組不代表資料已送達客戶端。清理錯誤與 PHP 最終結束原因分開保存；逾時只代表呼叫者停止等待，背景清理可能仍在進行，回傳快照不會被事後改寫。

## GitHub 審查回歸

[finally 前保留回傳值](https://github.com/HazelnutParadise/phego/pull/74#discussion_r4434629235)、[解構取代回傳時釋放原值](https://github.com/HazelnutParadise/phego/pull/74#discussion_r4434629238)、[局部值清理後重查宿主停止](https://github.com/HazelnutParadise/phego/pull/74#discussion_r4434629239)均有先失敗、修正後通過的[回歸證據](evidence/W-14.json)。對應 REQ-009、REQ-020、REQ-022、REQ-040；T-017、T-018、T-039、T-040、T-043、T-044、T-079、T-080。

內部 `completion` 的按值回傳持有一份邏輯所有權，在 finally 前取得；巢狀轉傳移動該所有權，不額外保留。結果被取代或忽略時消耗一次，釋放造成的新解構例外也必須繼續傳遞。局部值清理後再檢查取消、writer 失敗與配額停止，避免較早的 PHP 例外掩蓋宿主停止。

`outputFilter` 的位元組結果由未來 VM adapter 先完成型別轉換，成功時使用 `endNormal`；控制結果不拿來代替正常輸出字串。真正 PHP 的參照回傳、呼叫結果是否被使用，以及忽略運算式對解構時機的影響，仍需 VM 提供明確資訊，這次局部核心不宣稱涵蓋。
