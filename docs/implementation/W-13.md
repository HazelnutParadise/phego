# W-13｜PHP 程式可以執行完整物件行為及可觀察的生命週期

規格工作包：物件與邏輯生命週期。階段：M3。負責角色：Runtime維護者。

實作狀態：PHP 8.5.12 的物件與邏輯生命週期操作已實作，32／64 位元局部對照已執行。完整產品情境驗收為 `not_run`，目前沒有可執行完整 PHP 原始碼的引擎。跨循環弱參照復活已有使用者核准的相容性限制。lazy rollback 連續案例也使固定 PHP 記憶體損毀，使用者已另外核准明列限制後合併；兩類受阻案例都不計通過。第三項 Stringable argument 解構例外後進入條件 body，以及第四項轉換中 unset alias 再 clone 原物件，都有不安全原生結果。使用者已於 2026-11-03 明確核准保留 Go 安全行為並明列這兩項額外限制，兩案不計相容通過，其餘驗收與最新審查全數通過後允許合併。

## 局部結果與交付限制

本輪使用既有 worktree 與 PR #73，已合入 `origin/main` 的 W-12／W-14。設計取捨見 [W-13 物件模型](../decisions/W-13-objects.md)。

- 809 個案例分別以兩種固定 PHP 8.5.12 映像產生參考結果，Go 操作逐欄位比對通過。案例包含方法、具名／參照參數、static／instance 區別、magic property、hook frame、lazy ghost／proxy、clone、enum、資源、WeakMap、shutdown，以及 64 組物件圖。
- 請求隔離測試會拒絕藏在陣列或 reference 中的外來活值，並確認失敗前沒有部分認領或改寫目的地。共享類別描述的八個平行請求也已跑過 race 檢查。
- W-14 的 frame、回傳值、清理例外、資源 cleanup context 與 shutdown 順序已接入。解構時不依賴 Go finalizer，並保存復活、重入、取消及大量循環的回歸。
- 固定映像的跨循環 WeakReference 復活案例在 arm64 崩潰、i386 留下不安全結果。使用者已核准保留 Go 的安全修正並明列相容性受阻，本例不得算通過。原始結果見 `evidence/W-13-gc-weak-diagnostic.json`。
- 這批證據驗證 runtime 操作及其 W-14 執行流程，沒有完成 PHP frontend／VM、以類別名稱進入的 static／建構呼叫整合、autoload／namespace、Closure／Reflection 公開介面、實際檔案／資料庫 I/O、完整 gc 公開函式、歷史版本、應用或競品效能驗收。相應完整情境由下列負責票整合，狀態不改成 pass。

## 輸入、狀態與失敗處理

輸入由入口驗證精確 release／platform profile、build profile、能力及資源上限。只有完成驗證的不可變產物可共用。可變值、錯誤與清理紀錄由當次操作或 Execution 擁有。

| 情境 | 處理與可觀察結果 | 驗證責任 |
|---|---|---|
| 正常輸入 | 依下列需求產生輸出、診斷與可比較副作用 | 本票實作與局部回歸 |
| null／缺少必要欄位 | 依該版本區分合法 null、缺參數與無效設定，回報具位置的錯誤 | 本票輸入邊界測試 |
| 空字串／空集合／零 | 分開驗證有效空輸入、零值與不合法上限，不能以通用空值判斷合併 | 本票輸入邊界測試 |
| 來源或外部服務失敗 | 保留來源缺失、外部錯誤、政策拒絕及未知分類，不能固定回傳成功 | 本票故障注入 |
| 重複／並行／重入 | 可共用的產物維持唯讀，拒絕跨請求活物件與失效 handle | 本票交錯與重入回歸 |
| 取消／部分成功／清理失敗 | 終止受控工作，只清理已取得的資源，記錄已提交副作用與不可中斷部分 | 本票中斷與清理回歸 |

每列由本票擁有局部行為測試；下列情境的最終驗收負責票負責完整整合，不重複宣稱同一證據已完成。與該票輸入不相容的列須在實作審查中附不適用理由。

## 需求與完成條件

- **REQ-012 呼叫與符號**：PHP 開發者可以使用具名／參照參數、動態呼叫、autoload 與命名空間。
  完成條件：參數規則、解析順序、存取權與 callback 次數符合基準。

- **REQ-018 完整物件語意**：PHP 開發者可以使用繼承、trait、enum、typed／readonly 屬性與目標版新功能。
  完成條件：存取權、物件身分、property hooks、lazy object 與 Reflection 相容。

- **REQ-019 受控資源**：PHP 開發者可以使用檔案、資料庫與其他 resource 並安全關閉。
  完成條件：種類、擁有者、代次與關閉狀態均受檢查。

- **REQ-020 確定的解構**：PHP 開發者可以取得符合版本基準的解構時機與副作用。

R6 把 called scope 保存於當次請求，以 `defer` 隨完整 callback frame 還原，權限判斷繼續使用 lexical scope。它增加一個請求內指標及保存／還原操作，方法呼叫仍是 0 B／0 次配置；五次樣本從 195.0～196.7 ns 變為 197.1～208.8 ns，這項時間是成本，不計效能勝出。資源一般操作的五次樣本為修正前 8.909～9.065 ns、修正後 8.876～9.148 ns，均零配置；明確 close 使用既有 owner／generation 查找與原 cleanup context，沒有新增重試或 deadline。原始樣本與 overlay 見 R6 證據。

代理轉接必須先保留 wrapper hook，再對真正變更的 backing 重做完整 metadata 查找。static-as-instance 的訊息使用目前 receiver class，對應 magic method 存在時抑制 notice，不能看 callback 是否被 guard 阻止。此修正只在 static 分支多做方法查找，一般 instance 分支不執行它。lazy 最後持有者檢查與 weak alias 寫入保留既有錯誤優先順序及內部 strict `assign` 契約。

Raw adapter 目前依有效類別名稱選實體宣告；明確指定祖先 private descriptor，以及完整公開 Reflection 的參數與 static／virtual 驗證尚未整合。這些未涵蓋條件不計為 PHP 相容通過。

來源驗證跨越 PHP realloc／free 的輸入尚未驗證。Go 會保留舊 backing array 的安全存活，這只保證不讀取已釋放的 Go 記憶體，不能推論未跑過的原生 allocator 情境相容。

基準原始碼、布局、各項配置與時間都保留原始樣本。動態 4 屬性的記憶體及部分小物件時間沒有勝過原始 main，不能以平均或較大物件的改善消除這些輸項。
