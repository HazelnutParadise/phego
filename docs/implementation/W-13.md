# W-13｜PHP 程式可以執行完整物件行為及可觀察的生命週期

規格工作包：物件與邏輯生命週期。階段：M3。負責角色：Runtime維護者。

實作狀態：PHP 8.5.12 的物件與邏輯生命週期操作已實作，32／64 位元局部對照已執行。完整產品情境驗收為 `not_run`，目前沒有可執行完整 PHP 原始碼的引擎。跨循環弱參照復活已有使用者核准的相容性限制。lazy rollback 連續案例也使固定 PHP 記憶體損毀，使用者已另外核准明列限制後合併；兩類受阻案例都不計通過。

## 局部結果與交付限制

本輪使用既有 worktree 與 PR #73，已合入 `origin/main` 的 W-12／W-14。設計取捨見 [W-13 物件模型](../decisions/W-13-objects.md)。

- 222 個案例分別以兩種固定 PHP 8.5.12 映像產生參考結果，Go 操作逐欄位比對通過。案例包含方法、具名／參照參數、static／instance 區別、magic property、hook frame、lazy ghost／proxy、clone、enum、資源、WeakMap、shutdown，以及 64 組物件圖。
- 請求隔離測試會拒絕藏在陣列或 reference 中的外來活值，並確認失敗前沒有部分認領或改寫目的地。共享類別描述的八個平行請求也已跑過 race 檢查。
- W-14 的 frame、回傳值、清理例外、資源 cleanup context 與 shutdown 順序已接入。解構時不依賴 Go finalizer，並保存復活、重入、取消及大量循環的回歸。
- 固定映像的跨循環 WeakReference 復活案例在 arm64 崩潰、i386 留下不安全結果。使用者已核准保留 Go 的安全修正並明列相容性受阻，本例不得算通過。原始結果見 `evidence/W-13-gc-weak-diagnostic.json`。
- 這批證據驗證 runtime 操作及其 W-14 執行流程，沒有完成 PHP frontend／VM、autoload／namespace、Closure／Reflection 公開介面、實際檔案／資料庫 I/O、完整 gc 公開函式、歷史版本、應用或競品效能驗收。相應完整情境由下列負責票整合，狀態不改成 pass。
- 新增的 declared／dynamic rollback 各自於兩種固定映像成功執行，Go 符合其檢查點結果。連續執行會使兩種 PHP 映像記憶體損毀，使用者已另外核准明列限制後合併，連續案例仍不計為通過。原始結果見 `evidence/W-13-lazy-rollback-diagnostic.json`。
- 正式產生器將兩個 rollback 單案分別執行，再合併精確觀察，兩種寬度均成功產生 222 案。原有 220 案的結果逐欄位維持相同。連續輸入保存在獨立 diagnostic，其崩潰結果不計相容通過。獨立程式審查的具體參照計數缺陷已修復並重跑回歸。
