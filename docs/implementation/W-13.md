# W-13｜PHP 程式可以執行完整物件行為及可觀察的生命週期

規格工作包：物件與邏輯生命週期。階段：M3。負責角色：Runtime維護者。

實作狀態：PHP 8.5.12 的物件與邏輯生命週期操作已實作，32／64 位元局部對照已執行。完整產品情境驗收為 `not_run`，目前沒有可執行完整 PHP 原始碼的引擎。跨循環弱參照復活已有使用者核准的相容性限制。lazy rollback 連續案例也使固定 PHP 記憶體損毀，使用者已另外核准明列限制後合併；兩類受阻案例都不計通過。第三項 Stringable argument 解構例外後進入條件 body，以及第四項轉換中 unset alias 再 clone 原物件，都有不安全原生結果，正等待使用者獨立裁決，尚不可合併。

## 局部結果與交付限制

本輪使用既有 worktree 與 PR #73，已合入 `origin/main` 的 W-12／W-14。設計取捨見 [W-13 物件模型](../decisions/W-13-objects.md)。

- 510 個案例分別以兩種固定 PHP 8.5.12 映像產生參考結果，Go 操作逐欄位比對通過。案例包含方法、具名／參照參數、static／instance 區別、magic property、hook frame、lazy ghost／proxy、clone、enum、資源、WeakMap、shutdown，以及 64 組物件圖。
- 請求隔離測試會拒絕藏在陣列或 reference 中的外來活值，並確認失敗前沒有部分認領或改寫目的地。共享類別描述的八個平行請求也已跑過 race 檢查。
- W-14 的 frame、回傳值、清理例外、資源 cleanup context 與 shutdown 順序已接入。解構時不依賴 Go finalizer，並保存復活、重入、取消及大量循環的回歸。
- 固定映像的跨循環 WeakReference 復活案例在 arm64 崩潰、i386 留下不安全結果。使用者已核准保留 Go 的安全修正並明列相容性受阻，本例不得算通過。原始結果見 `evidence/W-13-gc-weak-diagnostic.json`。
- 這批證據驗證 runtime 操作及其 W-14 執行流程，沒有完成 PHP frontend／VM、以類別名稱進入的 static／建構呼叫整合、autoload／namespace、Closure／Reflection 公開介面、實際檔案／資料庫 I/O、完整 gc 公開函式、歷史版本、應用或競品效能驗收。相應完整情境由下列負責票整合，狀態不改成 pass。
- 新增的 declared／dynamic rollback 各自於兩種固定映像成功執行，Go 符合其檢查點結果。連續執行會使兩種 PHP 映像記憶體損毀，使用者已另外核准明列限制後合併，連續案例仍不計為通過。原始結果見 `evidence/W-13-lazy-rollback-diagnostic.json`。
- 正式產生器將兩個 rollback 單案分別執行，再合併精確觀察。最新矩陣為每種寬度 510 案，已提交的 463 案全部維持相同。R2 新增 76 案處理九項 Codex 意見，R3 再增 135 案處理七項新意見及三項獨立審查發現。涵蓋 private／static 查找、NUL 名稱、enum intrinsic readonly、implicit Stringable、浮點精度、return frame 次序、typed reference、callable 與例外鏈。失敗重播、控制案例與修正結果見 [R2](evidence/W-13-r2-review.json)／[R3 審查證據](evidence/W-13-r3-review.json)。R4 新增 30 案處理四項最新意見，涵蓋 WeakMap 比較、write-only isset、callable 及 method scope；原生區辨、失敗回歸及索引成本見 [R4 證據](evidence/W-13-r4-review.json)。R5 新增 47 案處理六項最新意見與獨立審查發現的相對型別回歸，包含繼承／重新宣告／private／trait 的來源身分、typed-source 重入順序、alias unset／rebind、RHS 存活、getter 自身 isset、proxy clone 失敗及完整例外鏈，見 [R5 證據](evidence/W-13-r5-review.json)。

## 輸入、狀態與失敗處理

輸入由入口驗證精確 release／platform profile、build profile、能力及資源上限。只有完成驗證的不可變產物可共用。可變值、錯誤與清理紀錄由當次操作或 Execution 擁有。

| 情境 | 處理與可觀察結果 | 驗證責任 |
|---|---|---|
| 正常輸入 | 依下列需求產生輸出、診斷與可比較副作用 | 本票實作與局部回歸 |
| null／缺少必要欄位 | 依該版本區分合法 null、缺參數與無效設定，回報具位置的錯誤 | 本票輸入邊界測試 |
| 空字串／空集合／零 | 分開驗證有效空輸入、零值與不合法上限，不能以通用空值判斷合併 | 本票輸入邊界測試 |
| 來源或外部服務失敗 | 保留來源缺失、外部錯誤、政策拒絕及未知分類，不能固定回傳成功 | 本票故障注入 |
| 重複／並行／重入 | 可共用的產物維持唯讀，拒絕跨請求活物件與失效 handle | 本票交錯與重入回歸 |
| 取消／部分成功／清理失敗 | 終止受控工作，只清理已取得的資源，記錄已提交副作用與不可中斷部分 | 本票中斷與清理回歸 |

每列由本票擁有局部行為測試；下列情境的最終驗收負責票負責完整整合，不重複宣稱同一證據已完成。與該票輸入不相容的列須在實作審查中附不適用理由。

R2 審查同時採用不增加本機配置級距的 `materialized` bool，取代宣告物件屬性檢視的空 map。單次及重複檢視從 296 B／4 次配置降為 248 B／3 次。clone 的配置結果與完整三次樣本見審查回歸證據。零屬性 lazy 的原單元 fixture 改為具有實體屬性，保留「未初始化不解構」斷言；固定 PHP 的零屬性普通物件行為另有精確對照，沒有放寬預期。

R3 將型別拆分改為 `iter.Seq[string]` 逐段讀取，無參數、回傳 int 的方法呼叫由 32 B／2 次配置降至 0 B／0 次。enumKind 使用原有 padding，classSpec 實測保持 184 B。這些量測沒有省略型別、owner、scope 或取消檢查。

R4 scoped 查找改用既有方法索引。1024 個無關方法的小寫 public 名稱，五次樣本由 6292～6360 ns 降至 18.71～19.37 ns，均為零配置。大寫 private 名稱則新增 8 B／一次正規化配置，三次樣本由 3108～3124 ns 降至 32.26～32.37 ns。此成本換取不隨方法數線性成長，不宣稱所有名稱都零配置。完整原始樣本與 Go overlay 重播方式見 R4 證據。

R4 的 private／protected `__invoke` 控制只證明 callable 驗證與既有呼叫核心，完整 frontend 裸物件分派仍未驗收。宣告警告的原生輸出見 [獨立探針](evidence/W-13-r4-invoke-probe.json)，矩陣的 PHP 輸入明確處理這些警告，不宣稱 Go frontend 診斷已完成。

R5 clone 改為一次複製／分離加一次 schema 掃描，並把單一來源 hold 的 slice 改成 stack 值。256 個 typed 屬性的五次樣本由 105616～114549 ns 降至 19204～19659 ns。plain 256 屬性由 18672 B／3 次配置降至 18592 B／2 次，dynamic 256 也少一次配置。typed-source 的 PHP 容量規則另有保留成本：兩個來源由原 cap 2 改成 cap 4，在此 host 多保留 32 B，不能從穩態 clone B/op 推論總保留記憶體。原始樣本及重跑方式見 R5 證據。

來源驗證跨越 PHP realloc／free 的輸入尚未驗證。Go 會保留舊 backing array 的安全存活，這只保證不讀取已釋放的 Go 記憶體，不能推論未跑過的原生 allocator 情境相容。

基準原始碼、布局、各項配置與時間都保留原始樣本。動態 4 屬性的記憶體及部分小物件時間沒有勝過原始 main，不能以平均或較大物件的改善消除這些輸項。

第三個不安全原生輸入與 Go 安全測試的證據見 [argument 解構診斷](evidence/W-13-argument-destructor-diagnostic.json)，狀態為等待使用者裁決，不計相容通過。先前兩項核准不涵蓋這個輸入。

第四個指定輸入在 `__toString` 中 unset global alias，再 clone 原物件。固定 arm64 exit 139，i386 回報 target SIGSEGV 後於 120 秒逾時。[原始證據](evidence/W-13-reference-clone-diagnostic.json)保留來源與命令。[`TestW13PendingReferenceCloneSafety`](../../internal/runtime/object_review_r5_safety_test.go#L11) 在 Go 兩種寬度安全完成、原 alias 保持不存在，shutdown 清空物件與 typed sources；這是宿主安全測試，不計 PHP 相容通過，也尚未取得合併裁決。

`python3 tools/validate_docs.py` 已通過 34 項文件檢查，產品情境仍為 `not_run`。正式雙寬度參考重產已完成。最新 head 的 Codex 審查、遠端 CI、ready 與 merge 以 [PR #73](https://github.com/HazelnutParadise/phego/pull/73) 的即時紀錄為準，不由本機測試推論。原始需求與完整產品情境保持規劃狀態及 `not_run`。
