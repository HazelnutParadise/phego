2026-11-07 起快照改為第 3 版，不必再像上一段那樣手動重建舊正文。除了整段首頁新聞摘要 `news_sha256`，`news` 依頁面順序逐則記錄消息的 id（例如 `2026-11-05-1`）、`<time datetime>`、標題，以及該則 `<article>` 原始標記的 SHA-256。`compare` 依 id 列出 `news_added`、`news_removed`、`news_changed`，每則的新舊紀錄放在 `changes`。整段摘要仍然保留，用來抓出只改順序或消息之間空白的變化。只要有一則消息不符合首頁的固定標記、消息之間夾了其他內容、第一則之前或最後一則之後不是首頁固定的外框，或一則都找不到，`observe` 就回報錯誤並指出第幾則，不會回傳較少或空的清單。所以首頁若改版，連同各系列的發布資料都要等工具更新後才能再比對。基準在同一個變更中改成第 3 版，新聞與各系列紀錄都取自 2026-11-07 的實際觀察，整段摘要仍是 `94798b73…`。工具不再接受第 2 版快照，舊的觀察檔要重跑 `observe`。對實際首頁執行 `observe` 得到 25 則消息，id 與標題和另用正規表示式直接從頁面抽出的結果逐一相同。把上一段重建的 2026-11-05 正文做成第 3 版快照，與 2026-11-07 的觀察比較，回傳 `news_added: [2026-11-05-1]`、`news_removed: [2026-07-30-2]`、`news_changed: []`，和人工重建的結論相同。

工具追蹤已列出的維護中系列、發布 tag、原始碼摘要、公告網址、公告正文摘要，以及官方首頁新聞的整段摘要與逐則紀錄；變化只列為待人工審查。它不解讀公告內容、不直接更新基準或來源鎖、不宣稱 PHP 語意相容，也不涵蓋所有歷史版本。只擷取官方頁面 `layout-content` 正文；若網頁結構改變會回報錯誤。官方首頁新聞另行比對，以保留安全公告變更線索；若未來安全提醒只出現在橫幅、沒有出現在首頁正文或發布資料，這個工具仍可能漏掉。來源錯誤、限流或資料不完整會回報失敗，不會當成沒有變更。

GitHub API 的 `GITHUB_TOKEN` 為選用，只送往 `api.github.com`；未登入實測曾收到 HTTP 403 限流，使用既有 GitHub 憑證後重跑成功。不要把憑證寫入檔案或記錄。
