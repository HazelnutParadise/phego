# W-04｜維護者可以用官方測試比較參考 PHP 與受測引擎

規格工作包：建立官方測試與差異runner。階段：M0。負責角色：相容性測試維護者。

實作狀態：`not_started`。驗收狀態：`not_run`。本 draft 目前只提交實作計畫，沒有可執行 PHP 引擎。

來源：[規格1.1.2](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/spec/specification.zh-TW.md)、[工作包原始記錄](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/data/phego-work-packages.json)、[需求](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/data/phego-requirements.json)、[驗收情境](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/data/phego-acceptance-tests.json)。

## 交付行為與實作順序

1. 支援PHPT所需sections、CLI與CGI介面。
2. 建立官方PHP與受測程式的獨立執行環境。
3. 實作結果分類、輸出正規化白名單與副作用記錄。

交付物：PHPT runner、差異測試器、結果分類fixture。

規格依賴：W-02、W-03。

依規格依賴即可開始；各子能力的適用平台與來源鎖必須明示。

先驗證這張票的局部交付，再把證據交給對應的完整產品驗收負責票。依賴未完成時可準備 fixture 與預期結果，不能宣稱已通過產品情境。

這張票的局部退出條件：已知通過、失敗、skip、unsupported與runner缺口均能正確分類，不靠Phego先完成才能驗證runner。

測試入口優先經已存在的公開入口或獨立工具，參考引擎、外部服務與副作用使用鎖定的受限環境。工具票可用受控替身驗證分類，替身不能支持 PHP 或真實應用相容聲明。

## 本 draft 與後續實作的檢查

- 本輪只做文件與追蹤驗證：`python3 tools/validate_docs.py`、`python3 -m unittest discover -s tools -p 'test_*.py'`。文件通過不構成上述 PHP 情境通過。

- 有 Go 模組後，實作交付須執行 `gofmt` 檢查、`CGO_ENABLED=0 go test ./...`、`go vet ./...`。並行變更新增 `go test -race ./...`，race 需要的建置工具與預設 Pure-Go 核心依賴分開。

- 格式解析與驗證器加入 fuzz 回歸；native 加入實際 ABI／指標／GC 壓力與後端差異；Web 與網站加入真實渲染及互動。這些命令及測試入口尚待實作，沒有宣稱本輪執行。

- Ready for review 前提交實際程式、測試位置、命令、commit、環境、原始結果、相容與安全差異，以及所有未涵蓋條件。只合併這份計畫不能關閉實作 issue。

## 相容、安全與範圍

維持 Go 單函式嵌入、預設不依賴 cgo／LLVM、第一版 PHP 起的全部歷史範圍、有界 goroutine、請求隔離與 Apache／Nginx FastCGI。任何後端都保留能力檢查及取消語意，正式執行不回退 Zend。

本票不發布軟體、不部署正式環境、不使用真實付款或郵件、不改第三方 PHP 程式來規避相容問題。付費、金鑰、正式權限、破壞性資料處理及產品方向變更需另外取得明確授權。
