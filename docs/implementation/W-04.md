## 局部實作進度

`tools/phpt_runner.py` 以 LF 區分 PHPT 原始行，保留獨立 CR 及區段位元組，並對缺漏或重複區段提供錯誤位置；`tools/phpt_results.py` 依提供的觀察結果區分通過、失敗、環境跳過、未支援、逾時、預期失敗及非預期通過。分類結果標示 `supplied_observation`，不能證明測試曾執行。互斥或格式無效的預期區段、轉送測試及負數結束碼都列為 runner 缺口。

`python3 tools/phpt.py inspect <檔案>` 可檢查單一 PHPT 的區段與摘要，不執行 PHP；缺少必要預期區段時會顯示修正提示。輸入須為不超過 8 MiB 的一般檔案，缺少安全開檔旗標的平台會明確拒絕。

`tools/phpt_diff.py` 可比較提供的觀察資料，包括 stdout、stderr、結束碼與副作用，並拒絕測試身分或版本平台不一致。未執行或不支援的結果保留為不可比較；此工具不證明資料來源或命令曾執行。

`python3 tools/phpt_compare.py reference.json candidate.json` 可讀取兩份觀察資料並輸出比對 JSON；`--help` 說明欄位與退出碼。輸入檔上限為 8 MiB，JSON 數字文字上限為 4096 字元，若 Python 自身設定更低的整數轉換上限，則沿用該限制並回報原因；無法保留原十進位值的小數會報錯，避免誤判一致。直接呼叫 `compare()` 時，已轉為 Python float 的來源精度無法還原。此入口不執行測試，也不改變 PHP 程式的數值行為。

`tools/phpt_sandbox.py` 可在受限容器中執行單份 PHP 來源，必須提供 digest 固定的映像、絕對執行檔路徑與 `linux/amd64`、`linux/arm64` 或 `linux/386` 平台，並限制時間、輸出與資源。這是局部執行能力，已接入部分 PHPT 區段，CGI 與副作用比對尚未整合。清理無法確認時回報 runner 錯誤。

在本機 Docker 以映像 `i386/php@sha256:07e835693e041c2a79cd7a3a7a0fda4b2a8d65c6f93bd89bb8dad5c616f28049`、`linux/386` 執行 `<?php echo PHP_INT_SIZE, "\n";`，輸出 `4`，執行結束碼為 0；以同映像指定 `linux/amd64` 時建立容器失敗，未回報通過。這是模擬 32 位元的預建映像探查，未證明執行檔由鎖定來源建置，也不是 Phego 相容性驗收。局部測試為 `tests/runner/test_phpt_sandbox.py`。

`python3 tools/phpt_execute.py --image <映像摘要> --executable <路徑> --platform <平台> --release <版本> <案例.phpt>` 串接解析、容器與結果分類。執行前以該映像查核 `PHP_VERSION` 與整數位元組數，僅接受三段式版本；這是執行檔自報資訊，不能證明來源身分。支援 `TEST`、`FILE`、`EXPECT`／`EXPECTF`、`XFAIL` 與局部 `SKIPIF`、`INI`、`ENV`、`CLEAN`、`STDIN`、CGI 的 `GET`／`POST`／`COOKIE`／`EXPECTHEADERS`；外部預期檔及其他未支援區段會在執行案例前回報 `runner_gap` 並指出區段。`INI` 目前只依 PHP 8.5.12 官方規則處理有界設定，並只套用於 `FILE`；不支援的版本、替代符號與 shell 展開會回報缺口。`ENV` 同樣只支援 PHP 8.5.12 的有界設定，套用於 `SKIPIF` 與 `FILE`，執行器會改寫的 CGI 等名稱回報缺口；空值會移除同名環境變數，設定需要容器內的 `env` 工具。`CLEAN` 目前只支援 PHP 8.5.12，在 `FILE` 完成後於相同目錄執行，沿用 `ENV` 但不套用測試的 `INI`；清理逾時、stderr、執行狀態不明或容器清理未確認時回報缺口。PHP 8.5.12 的一般 CLI 案例也會依官方執行器設定 `FILE` 的預設請求環境，`SKIPIF` 與 `CLEAN` 依各自階段設定，先清除官方會重設的映像環境變數再套用測試設定；其他版本的預設環境尚未查證。回歸測試位於 `tests/runner/test_phpt_cli_environment.py`。CGI 案例需另指定 `--cgi-executable`，執行前獨立查核 CGI 執行模式、版本與整數位元組數；目前只支援 PHP 8.5.12，未支援的請求形式及無法可靠比較的數值標頭維持缺口。`STDIN` 只支援 PHP 8.5.12，最多 1 MiB，原始位元組只提供給 `FILE`；搭配 `INI` 或 `ENV` 時，容器內的暫時啟動腳本在執行 `FILE` 前移除。設定透過標準輸入傳給容器內 shell，不出現在宿主 Docker 命令列；容器內程序的命令列及環境仍可能包含設定。含 `SKIPIF` 的案例在同一個受限容器目錄中分別執行版本檢查、`SKIPIF` 與 `FILE`，每階段使用獨立 PHP 程序。程式呼叫與命令列都可明確提供附屬檔案，即使案例沒有 `SKIPIF` 也會載入。命令列使用 `--fixture 目標相對路徑=來源檔案`，可重複指定，最多 128 個檔案、合計 8 MiB；來源須是一般檔案，目的路徑不得越界或衝突。檔案逐一讀取，不能保證同時來自同一瞬間。跳過原因未經獨立確認時回報 `runner_gap`，不推測為環境跳過或未支援。副作用尚未完整紀錄，結果標示 `effects_complete: false`。容器清理無法確認時不得回報通過；主機終止或 Docker 延遲建立可能讓清理狀態無法確認。早期沒有對應版本探查的引擎維持缺口，不縮減歷史支援目標。

本機以 `linux/386` 的固定 PHP 8.5.12 預建映像執行 `tests/runner/phpt-fixtures/pass.phpt`，回報 `pass`、結束碼 0；版本不符案例回報 `runner_gap`。這是模擬架構的參考映像結果，不是 Phego 或完整 PHPT 相容性驗收。驗證位於 `tests/runner/test_phpt_execute.py`。另以同一映像實際驗證 `SKIPIF` 與 `FILE` 共用目錄、讀取明確提供的附屬檔案，並確認原因不明的跳過維持 `runner_gap`。相關隔離與串接回歸位於 `tests/runner/test_phpt_session.py` 與 `tests/runner/test_phpt_execute_session.py`。

目前只處理一般 EXPECT 與部分 EXPECTF 格式；原始正規表示式、外部預期檔與平台相關格式保留為 runner 缺口。完整 CLI／CGI 測試執行、來源確認、副作用記錄與引擎間差異比對尚未接上。本機回歸位於 `tests/runner/test_phpt_runner.py` 與 `tests/runner/test_phpt_results.py`。

## 輸入、狀態與失敗處理

輸入由入口驗證精確 release／platform profile、build profile、能力及資源上限。只有完成驗證的不可變產物可共用。可變值、錯誤與清理紀錄由當次操作或 Execution 擁有。

| 情境 | 處理與可觀察結果 | 驗證責任 |
|---|---|---|
| 正常輸入 | 依下列需求產生輸出、診斷與可比較副作用 | 本票實作與局部回歸 |
| null／缺少必要欄位 | 依該版本區分合法 null、缺參數與無效設定，回報具位置的錯誤 | 本票輸入邊界測試 |
| 空字串／空集合／零 | 分開驗證有效空輸入、零值與不合法上限，不能以通用空值判斷合併 | 本票輸入邊界測試 |
| 來源或外部服務失敗 | 保留來源缺失、外部錯誤、政策拒絕及未知分類，不能固定回傳成功 | 本票故障注入 |
| 重複／並行／重入 | 可共用的產物維持唯讀，拒絕跨請求活物件與失效 handle | 本票交錯與重入回歸 |
| 取消／部分成功／清理失敗 | 終止受控工作，只清理已取得的資源，記錄已提交副作用與不可中斷部分 | 本票中斷與清理回歸 |

每列由本票擁有局部行為測試；下列情境的最終驗收負責票負責完整整合，不重複宣稱同一證據已完成。與該票輸入不相容的列須在實作審查中附不適用理由。
