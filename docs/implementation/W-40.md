# W-40｜網站管理者可以觀測、重載、關閉及回復部署

規格工作包：維運、重載、遷移與回復。階段：M7。負責角色：維運整合維護者。

實作狀態：`not_started`。驗收狀態：`not_run`。本 draft 目前只提交實作計畫，沒有可執行 PHP 引擎。

來源：[規格1.1.2](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/spec/specification.zh-TW.md)、[工作包原始記錄](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/data/phego-work-packages.json)、[需求](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/data/phego-requirements.json)、[驗收情境](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/data/phego-acceptance-tests.json)。

## 交付行為與實作順序

1. 建立readiness、metrics、事件與管理權限。
2. 實作設定代次、drain、關閉與回復演練。
3. 提供非破壞的部署設定與資料相容檢查。

交付物：維運指南、觀測介面、切換／回復演練證據。

## 前置條件與整合

規格依賴：W-22、W-25、W-26、W-28、W-35。

依規格依賴即可開始；各子能力的適用平台與來源鎖必須明示。

先驗證這張票的局部交付，再把證據交給對應的完整產品驗收負責票。依賴未完成時可準備 fixture 與預期結果，不能宣稱已通過產品情境。

## 預定實作與測試位置

internal/web/、cmd/phego/、tests/operations/、docs/acceptance/。這些是待建立的位置，實際布局可在規格內調整，交付時須填寫真實檔案與行號。

## 輸入、狀態與失敗處理

輸入由入口驗證精確 release／platform profile、build profile、能力及資源上限。只有完成驗證的不可變產物可共用。可變值、錯誤與清理紀錄由當次操作或 Execution 擁有。

| 情境 | 處理與可觀察結果 | 驗證責任 |
|---|---|---|
| 正常輸入 | 依下列需求產生輸出、診斷與可比較副作用 | 本票實作與局部回歸 |
| null／缺少必要欄位 | 依該版本區分合法 null、缺參數與無效設定，回報具位置的錯誤 | 本票輸入邊界測試 |
| 空字串／空集合／零 | 分開驗證有效空輸入、零值與不合法上限，不能以通用空值判斷合併 | 本票輸入邊界測試 |
| 來源或外部服務失敗 | 保留來源缺失、外部錯誤、政策拒絕及未知分類，不能固定回傳成功 | 本票故障注入 |
| 重複／並行／重入 | 可共用的產物維持唯讀，拒絕跨請求活物件與失效 handle | 本票交錯與重入回歸 |
| 取消／部分成功／清理失敗 | 終止受控工作，只清理已取得的資源，記錄已提交副作用與不可中斷部分 | 本票中斷與清理回歸 |

每列由本票擁有局部行為測試；下列情境的最終驗收負責票負責完整整合，不重複宣稱同一證據已完成。與該票輸入不相容的列須在實作審查中附不適用理由。

## 需求與完成條件

- **REQ-028 Goroutine 請求模型**：網站管理者可以同時執行多個獨立 PHP 請求。
  完成條件：不同請求共享程式但不共享可變執行狀態。

- **REQ-032 高風險程序隔離**：平台管理者可以對需要硬性停止或較低信任的程式選用隔離 worker。
  完成條件：worker 受到 OS 權限與資源限制，崩潰不終止控制程序。

- **REQ-036 模式與稽核**：網站管理者可以在 compat、observe、enforce 下檢視或阻擋規則事件。
  完成條件：模式可辨識，強制能力與資源限制在各模式都有效。

- **REQ-046 既有資料共存**：網站管理者可以在遷移時保留相容的Session資料與Cookie。
  完成條件：舊後端與新後端之格式、TTL、ID與鎖定有雙向測試。

- **REQ-051 真實網站**：網站管理者可以在不改PHP原始碼的條件下遷移認證範圍內網站。
  完成條件：固定版本WordPress與Laravel fixture的主要流程與例外測試通過。

- **REQ-068 設定重載**：網站管理者可以安全替換站台設定而不混用請求狀態。
  完成條件：新代次原子發布，失敗保留舊設定，強制取消模式明確。

- **REQ-069 健康與觀測**：平台管理者可以分辨程序存活、服務可用與請求瓶頸。
  完成條件：提供有界metrics與可關聯事件，不公開祕密或管理端點。

- **REQ-070 平滑停止**：網站管理者可以在有期限的條件下停止服務。
  完成條件：停止接納、完成／取消工作、釋放資源，native程式不提早卸載。

- **REQ-071 遷移與回復**：網站管理者可以以可回復方式將現有網站切換至Phego。
  完成條件：設定差異、資料相容、測試副本與回切步驟俱全。

- **REQ-078 權限與修改範圍**：實作agent可以在授權範圍內完成與驗證工作。
  完成條件：已授權建立 HazelnutParadise/phego、使用 MIT 並推送本次規格與英文 README；正式引擎 release、付費、正式設定及資料刪改仍須另有授權。

## 驗收情境與證據

這張票的局部退出條件：不洩漏祕密，不無授權雙寫／刪資料，流量中可受控重載與關閉。

完整情境由下列指定票整合驗收。基礎票通過自己的退出條件，不會自動把尚需下游功能的情境標成 pass。所有情境目前均為 `not_run`。

測試入口優先經已存在的公開入口或獨立工具，參考引擎、外部服務與副作用使用鎖定的受限環境。工具票可用受控替身驗證分類，替身不能支持 PHP 或真實應用相容聲明。
