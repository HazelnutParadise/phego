# W-20｜宿主可以限制每次 PHP 執行的資源與外部能力

規格工作包：能力與配額核心。階段：M2。負責角色：安全Runtime維護者。

實作狀態：`not_started`。驗收狀態：`not_run`。本 draft 目前只提交實作計畫，沒有可執行 PHP 引擎。

來源：[規格1.1.2](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/spec/specification.zh-TW.md)、[工作包原始記錄](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/data/phego-work-packages.json)、[需求](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/data/phego-requirements.json)、[驗收情境](https://github.com/HazelnutParadise/phego/blob/6e2e701174a2f8d7afb0a884305007923684f1a9/docs/data/phego-acceptance-tests.json)。

## 交付行為與實作順序

1. 建立檔案、網路、DB、exec與callback能力。
2. 實作Execution、Engine與外部配置的分開計量。
3. 定義取消、過量輸入與安全事件錯誤。

交付物：能力介面、資源預算、安全錯誤契約。

## 前置條件與整合

規格依賴：W-01、W-05、W-08。

依規格依賴即可開始；各子能力的適用平台與來源鎖必須明示。

先驗證這張票的局部交付，再把證據交給對應的完整產品驗收負責票。依賴未完成時可準備 fixture 與預期結果，不能宣稱已通過產品情境。

## 預定實作與測試位置

internal/policy/、internal/runtime/、tests/policy/。這些是待建立的位置，實際布局可在規格內調整，交付時須填寫真實檔案與行號。

## 輸入、狀態與失敗處理

輸入由入口驗證精確 release／platform profile、build profile、能力及資源上限。只有完成驗證的不可變產物可共用。可變值、錯誤與清理紀錄由當次操作或 Execution 擁有。

| 情境 | 處理與可觀察結果 | 驗證責任 |
|---|---|---|
| 正常輸入 | 依下列需求產生輸出、診斷與可比較副作用 | 本票實作與局部回歸 |
| null／缺少必要欄位 | 依該版本區分合法 null、缺參數與無效設定，回報具位置的錯誤 | 本票輸入邊界測試 |
| 空字串／空集合／零 | 分開驗證有效空輸入、零值與不合法上限，不能以通用空值判斷合併 | 本票輸入邊界測試 |
| 來源或外部服務失敗 | 保留來源缺失、外部錯誤、政策拒絕及未知分類，不能固定回傳成功 | 本票故障注入 |
| 重複／並行／重入 | 可共用的產物維持唯讀，拒絕跨請求活物件與失效 handle | 本票交錯與重入回歸 |
| 取消／部分成功／清理失敗 | 終止受控工作，只清理已取得的資源，記錄已提交副作用與不可中斷部分 | 本票中斷與清理回歸 |

每列由本票擁有局部行為測試；下列情境的最終驗收負責票負責完整整合，不重複宣稱同一證據已完成。與該票輸入不相容的列須在實作審查中附不適用理由。

## 需求與完成條件

- **REQ-008 宿主函式註冊**：Go 開發者可以明確授權 PHP 呼叫特定 Go 函式。
  完成條件：簽章、權限、來源標記、重入與取消規則在註冊時驗證。

- **REQ-009 關閉與取消**：Go 開發者可以取消執行或有期限地關閉 Engine。
  完成條件：停止接納、取消與 drain 可觀察，已開始的輸出與副作用不被隱藏。

- **REQ-013 include 與 require**：PHP 開發者可以以相容作用域與路徑規則載入 PHP 檔案。
  完成條件：include_once 身分、回傳、失敗種類與讀取權限正確。

- **REQ-014 eval 與動態宣告**：PHP 開發者可以執行符合站台政策的動態 PHP 程式碼。
  完成條件：沿用同一版本、配額、來源標記與語意，不啟動外部 PHP。

- **REQ-019 受控資源**：PHP 開發者可以使用檔案、資料庫與其他 resource 並安全關閉。
  完成條件：種類、擁有者、代次與關閉狀態均受檢查。

- **REQ-022 初始化安全**：平台管理者可以在任何初始化步驟失敗時維持服務完整性。
  完成條件：只有已提交資源進入清理，下一請求不取得半成品。

- **REQ-026 可取消 VM**：平台管理者可以中止高成本 PHP 執行且釋放核心資源。
  完成條件：回邊、配置、函式與長操作有檢查點，錯誤可分類。

- **REQ-029 有界接納**：平台管理者可以限制連線、排隊與活躍 PHP 請求。
  完成條件：超過容量時在執行前拒絕，goroutine／body 緩衝不無界成長。

- **REQ-031 資源預算**：平台管理者可以限制運算、邏輯記憶體、輸出與外部資源。
  完成條件：超限在可控邊界拒絕，不把邏輯額度誤稱為 RSS 硬限制。

- **REQ-033 能力式 I/O**：平台管理者可以只授權 PHP 使用明確的檔案、網路、資料庫與宿主功能。
  完成條件：所有入口與後端經過同一能力檢查。

- **REQ-036 模式與稽核**：網站管理者可以在 compat、observe、enforce 下檢視或阻擋規則事件。
  完成條件：模式可辨識，強制能力與資源限制在各模式都有效。

- **REQ-037 路徑與 SSRF**：網站管理者可以防止 PHP 超出授權檔案與網路範圍。
  完成條件：實際使用時檢查根目錄、解析IP、重新導向與代理。

- **REQ-042 表單與上傳**：PHP 開發者可以使用相容的表單、Cookie與檔案上傳資料。
  完成條件：鍵轉換、重複欄位、深度、大小、暫存登錄及move_uploaded_file正確。

- **REQ-045 提早結束回應**：PHP 開發者可以使用fastcgi_finish_request後完成允許的後續工作。
  完成條件：回應關閉與Execution結束分開，名額、鎖與額度持續有效。

- **REQ-049 資料庫語意**：PHP 開發者可以使用已認證的PDO／mysqli功能。
  完成條件：placeholder、fetch、型別、交易、錯誤及連線重設相容。

- **REQ-059 VFS與寫入**：PHP 開發者可以在封裝環境使用一致路徑並存取授權可寫資料。
  完成條件：__FILE__、include、realpath與列舉一致，程式與資料區分開。

- **REQ-069 健康與觀測**：平台管理者可以分辨程序存活、服務可用與請求瓶頸。
  完成條件：提供有界metrics與可關聯事件，不公開祕密或管理端點。
