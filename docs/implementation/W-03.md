## 已實作的執行紀錄檢查

`python3 tools/traceability.py` 讀取驗收情境登錄，列出全部測試及 `not_run` 狀態。可加上 `--results <紀錄.json>` 檢查單一版本、平台、建置設定及 commit 的紀錄，輸出各狀態數量與原始紀錄。輸入為含 `records` 陣列的 JSON，每筆以 `test_id` 和 `status` 指定情境及結果；已執行或已分類的項目須附 `commit`、`command`、`profile`、`exit_code` 和 `evidence`。`profile` 含 `release`、`platform`、`build`，`evidence` 含相對於專案根目錄的 `path` 與 `sha256`。逾時或執行工具失敗等沒有結束碼的狀況可用 `null`，通過則必須是零。缺少項目保留 `not_run`，不會從總數消失。

檢查器驗證欄位、ID、單一設定、證據檔案及摘要，並保留原始紀錄供審查；摘要相符不能證明命令確實執行或結果正確。`product_acceptance` 固定為 `not_claimed`。目前尚未驗證 commit 是否存在、來源鎖、完整平台語意、歷史紀錄變更及未滿足依賴，不能用來宣布工作包或產品通過。受控資料的測試位於 `tools/test_traceability.py` 與 `tools/test_traceability_profile.py`，對應 REQ-072、REQ-076、REQ-079；不宣稱 T-143／144、T-151／152 或 T-157／158 已完成。

執行紀錄的結構格式見 [evidence-records.schema.json](../data/evidence-records.schema.json)，採 JSON Schema 2020-12。格式只檢查資料結構，不能核對測試 ID、重複記錄、檔案路徑或摘要、commit 與 profile 是否一致，也不能證明測試執行或通過。JSON Schema 將 `0.0` 視為整數，Python 工具會拒絕浮點數；以工具檢查結果為準。完整狀態轉移與完整證據格式仍待實作。

比較只檢查使用者提供的兩份快照，無法證明舊快照沒有被替換，也不能驗證命令、commit 或通過結果的真實性。產品驗收仍為 `not_claimed`；本工具不執行測試，不處理工作包依賴或完整狀態轉移。局部回歸位於 `tools/test_compare_evidence.py` 與 `tools/test_compare_no_loss.py`，對應 REQ-072、REQ-076，完整的 T-143／144、T-151／152 仍為 `not_run`。

## 能力主張格式與紀錄檢查

[capabilities.schema.json](../data/capabilities.schema.json) 定義版本 1 的能力主張格式，區分函式、類別、常數、擴充、INI、SAPI 與各項狀態。`python3 tools/capabilities.py --capabilities <能力清單.json> --results <執行紀錄.json>` 檢查格式、重複項、測試登錄及版本／平台／建置設定；只有主張 `supported` 時才必須提供執行紀錄及至少一個該設定的 `pass` 測試 ID。未支援、未驗證、政策拒絕、語意差異與失敗保留為不同狀態，不能以空清單代表完整支援。

檢查器在私人暫存目錄建立登錄、執行紀錄與證據快照，再呼叫既有追蹤檢查器；快照檔以排他建立，避免大小寫等檔案系統別名覆蓋登錄。能力清單、執行紀錄與測試登錄各限 1 MiB，證據檔合計限 64 MiB。能力清單及執行紀錄本身若是符號連結或特殊檔案會被拒絕；登錄與證據路徑的符號連結、特殊檔案、越界路徑及快照碰撞也會被拒絕。各檔案的快照不保證同時取自同一瞬間，讀取期間原地修改一般檔也不是原子操作。此工具使用 POSIX 檔案操作，已在 macOS 測試，其他平台須另行驗證。

資料格式只檢查結構，無法自行核對測試 ID、路徑、摘要、重複功能身分與測試結果；這些由檢查器另行處理。JSON Schema 將 `1.0` 視為整數，檢查器只接受整數 `1`。九個合成結構案例曾以隔離容器內的 `jsonschema` 4.25.1 與檢查器比對；這不代表涵蓋全部輸入。

檢查器不證明命令實際執行、commit 存在、測試是否足以證明該功能、清單是否完整或引擎是否真的提供功能；任意不相關的已通過測試也不能當成能力驗收證據。輸出固定標示 `verification_status: not_verified`、`product_acceptance: not_claimed`。目前沒有引擎產生的正式能力報告，REQ-003、T-005／006 與 W-03 完整驗收仍未通過。局部回歸位於 `tools/test_capabilities.py`。

## 工作包狀態主張與依賴檢查

`python3 tools/work_status.py --ledger docs/implementation/evidence/W-03-w01-status-claim.json` 可檢查 W-01 既有契約審查的單筆主張。此輸入只涵蓋 W-01，其他工作包顯示規劃預設，並不表示實際尚未開始；W-02、W-03 已在進行。檢查時本機 Git 必須有輸入所指的 commit，淺層 checkout 缺少它時會回報錯誤。

輸入是含 `events` 陣列的 JSON。每筆記錄工作包 `id`、`status`、非空 `reason`，以及含 `commit`、`path`、`sha256` 的 `evidence`。工具先檢查原始規劃與整合依賴，再依序檢查狀態轉換。未完成依賴不阻止獨立子工作進行；提出 `claimed_complete` 時，原始與整合依賴必須已有完成主張。重開前置工作後，已提出完成主張的下游必須重新開啟；前置工作再次提出完成主張也不會自動恢復舊的下游主張。

狀態以規劃資料的 `not_started` 為起點，可轉為 `in_progress`、`blocked` 或有證據的 `claimed_complete`。`in_progress` 可轉為 `blocked` 或 `claimed_complete`；`blocked` 與 `claimed_complete` 只能重新轉為 `in_progress`。每筆事件都需要原因與證據。

規劃檢查在私人暫存快照執行，並以同一份快照載入依賴資料，輸出四份登錄的摘要。快照只複製規劃所需的 Markdown、資料登錄、授權檔與明確連結的章節錨點內容；其他一般檔案只保留檔名及存在性，不讀取其內容。這些臨時空檔的摘要不作證據使用。除 `.git` 和 `__pycache__` 外，工作目錄中的符號連結與特殊檔案會被拒絕。快照最多 10,000 個檔案，需讀取的單檔最多 64 MiB、合計最多 512 MiB；既有文件驗證器有 15 秒時限。快照不保證所有原始檔案來自同一瞬間，也不證明目前工作目錄未再變動。

每份證據必須是指定 commit 內不超過 8 MiB 的一般檔，摘要從 Git 物件核對，不以工作目錄的同名檔案替代。工具限制輸入為 1 MiB 與最多 10,000 個事件。它無法判斷證據內容是否足以通過工作包閘門，也不能防止使用者替換整份 ledger；`claimed_complete` 是主張，`verification_status` 固定為 `not_verified`，產品驗收固定為 `not_claimed`。規劃預設狀態與真實現況仍須分開核對。

局部驗證位於 `tools/test_work_status.py`，對應 REQ-076、REQ-079；完整的 T-151／152、T-157／158 仍為 `not_run`。能力清單的引擎產生與完整性檢查、測試執行結果的真實性與正式完成驗收尚未實作。

目前檔案安全讀取使用 POSIX 的 `openat` 與 `O_NOFOLLOW`，已在 macOS 測試；其他平台須另行驗證。原本的 `docs/implementation/evidence/W-03.json` 是先前文件檢查的歷史紀錄，不是這次程式驗收結果。

## 局部測試執行觀察

`python3 tools/w03_local_gate.py --commit <完整 commit SHA>` 從指定 Git commit 的一般檔建立私人快照，核對 Git 物件及執行中的工具內容，再比對 [固定檢查清單](../../tools/w03-local-checks.json)與實際發現的測試。它親自執行清單，記錄每項開始、結果與結束；缺項、跳過、失敗、錯誤或逾時不會回報通過。報告包含 commit、tree、工具與規劃資料摘要、Python 及執行平台資訊。

這個入口只執行可信任的提交，不是安全沙箱，也不接受匯入的執行結果作為親自觀察的證據。工作目錄中未提交的檔案不會納入；工具本身須與指定提交一致。它目前只支援 SHA-1 Git 儲存庫與 UTF-8 路徑，使用 POSIX 操作；目前已在 macOS 測試，Linux 完整執行仍待驗證。符號連結、submodule 和超過限制的檔案會被拒絕。測試與工具可能讀取本機檔案或網路，歷史參考引擎和不可信測試仍須另置於受限容器。

此入口對應 REQ-072、REQ-076 與 REQ-079，不宣稱 T-143／144、T-151／152 或 T-157／158 已通過。結果只描述此次清單的實際觀察，不證明測試涵蓋產品需求，也不確認 W-01、W-02 的完成狀態。`package_acceptance` 與 `product_acceptance` 均為 `not_claimed`。局部回歸見 `tools/test_w03_local_gate.py`、`tools/test_w03_local_snapshot.py`、`tools/test_w03_local_manifest.py` 與 `tools/test_w03_gate_cli.py`。完整產品情境和 W-03 工作包驗收仍為 `not_run`。

早期版本在 macOS 的暫存提交 `aca371cefed2396f6b5ca92d9c63157888be2956` 執行 115 項檢查時，有兩個子測試各在三秒上限內未完成，結果為 `error`。當時另一組完整測試同時執行，不能據此確定逾時根因。 [原始結果](evidence/W-03-local-gate-concurrent-failure.json.gz)解壓後 SHA-256 為 `6152e692e34e16b69bdc771ac5ea31b51ac27d15ce26073a5532162d5a554651`。該暫存提交不在正式分支上，此紀錄不是目前版本的驗收結果。

## 輸入、狀態與失敗處理

輸入由入口驗證精確 release／platform profile、build profile、能力及資源上限。只有完成驗證的不可變產物可共用。可變值、錯誤與清理紀錄由當次操作或 Execution 擁有。

| 情境 | 處理與可觀察結果 | 驗證責任 |
|---|---|---|
| 正常輸入 | 依下列需求產生輸出、診斷與可比較副作用 | 本票實作與局部回歸 |
| null／缺少必要欄位 | 依該版本區分合法 null、缺參數與無效設定，回報具位置的錯誤 | 本票輸入邊界測試 |
| 空字串／空集合／零 | 分開驗證有效空輸入、零值與不合法上限，不能以通用空值判斷合併 | 本票輸入邊界測試 |
| 來源或外部服務失敗 | 保留來源缺失、外部錯誤、政策拒絕及未知分類，不能固定回傳成功 | 本票故障注入 |
| 重複／並行／重入 | 可共用的產物維持唯讀，拒絕跨請求活物件與失效 handle | 本票交錯與重入回歸 |
| 取消／部分成功／清理失敗 | 終止受控工作，只清理已取得的資源，記錄已提交副作用與不可中斷部分 | 本票中斷與清理回歸 |

每列由本票擁有局部行為測試；下列情境的最終驗收負責票負責完整整合，不重複宣稱同一證據已完成。與該票輸入不相容的列須在實作審查中附不適用理由。

## 驗收情境與證據

這張票的局部退出條件：任何需求遺漏測試、循環依賴或未執行測試卻標完成都會失敗。

完整情境由下列指定票整合驗收。基礎票通過自己的退出條件，不會自動把尚需下游功能的情境標成 pass。所有情境目前均為 `not_run`。

測試入口優先經已存在的公開入口或獨立工具，參考引擎、外部服務與副作用使用鎖定的受限環境。工具票可用受控替身驗證分類，替身不能支持 PHP 或真實應用相容聲明。

## 相容、安全與範圍

維持 Go 單函式嵌入、預設不依賴 cgo／LLVM、第一版 PHP 起的全部歷史範圍、有界 goroutine、請求隔離與 Apache／Nginx FastCGI。任何後端都保留能力檢查及取消語意，正式執行不回退 Zend。
