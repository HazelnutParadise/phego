# 開發者診斷需求

追蹤：REQ-101、T-201、T-202。狀態：`planned`；驗收為 `not_run`。原始規格 1.1.2 的 100／200 基準保留於 Git 來源提交，本需求為後續追加。

Phego 的錯誤訊息須讓開發者看懂發生什麼、在哪裡，以及有可靠建議時可以怎麼修正。介面可以借鏡 Rust 編譯器的來源標示與說明，但不依賴顏色，也不要求複製 Rust 的措辭。

## 必要內容

- 可分類的錯誤或警告、清楚的原因與穩定識別方式。
- 來源可用時，提供檔案、行列、位元組範圍與對應標記；來源不可用時明確說明。
- 有足夠證據時提供具體建議；無法確認時說明限制，不編造修法。可能改變語意的建議不能標示為可自動套用。
- 終端與機器可讀結果呈現相同的問題、位置與建議。顏色關閉或非互動環境仍可閱讀。
- 來源片段、路徑和敏感值依安全政策遮蔽；診斷的數量與大小受限。
- PHP 程式可見的警告、例外及輸出維持選定版本的相容行為；開發者診斷以獨立通道提供。

## 驗收

1. 語法錯誤的固定輸入必須指出正確檔案和範圍，清楚說明問題；可確定修法的案例須提供具體建議。
2. 無來源、非法 UTF-8、多行或超長輸入必須有可追蹤且受限的結果，不能偽造位置或漏出受保護內容。
3. 不確定修法不能標示為可自動套用；終端與機器可讀結果的主要資訊須一致。
4. 相同 PHP 程式在同一 profile 下，開發者診斷開關不得改變 PHP 可見的輸出、警告、例外或執行結果。

## 實作與驗收責任

W-09 提供來源範圍與語法診斷，W-10 處理版本相容診斷，W-08 與 W-35 提供 Go／CLI 的可用輸出。W-42 負責完整驗收，須涵蓋這些入口與 PHP 可見行為；在可執行引擎與入口完成前，維持未執行狀態。

參考：[Rust Compiler Development Guide：Errors and lints](https://rustc-dev-guide.rust-lang.org/diagnostics.html)。
