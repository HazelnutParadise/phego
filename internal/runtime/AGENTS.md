# Rules for `internal/runtime`

Each line is a condition and what to do. The story behind a line, with the failed routes and the evidence files, is in the commit that added it (`git log -S '<words from the line>'`). Every PHP-visible rule here was measured on the pinned PHP 8.5.12 images; verify there before changing one.

## VM and execution

- Testing what an instruction leaves in a register with hand-written bytecode: disable liveness with `withoutLiveness` in `vm_refs_test.go` (1024 unused Value registers and 65536 Checkpoints). `vmLiveness` releases dead registers, so tests of register leaks pass on buggy code without it.
- Sharing code on a hot path: do not route a `completion` return through one more non-inlined frame. It is a large struct and the extra frame cost 10-33% on `BenchmarkOutputWrite`; the duplicated echo/write body stays. Measure on CI before deduplicating, and keep VM handlers from returning `completion` by value on the fast path.
- Returning a value through `finally`: dereference it and take a single owner before `finally` runs, and hand it to a nested call with `returnOwned`. Retaining only before locals are released lets `finally` free it early. `replaceOwnedCompletion` holds the new value before releasing the old one and handles a throw during that release.
- After frame locals and every return owner are cleaned up: check sticky host termination again. `heap.freeArray` keeps only the first destructor error, and a later destructor can set a cancellation, writer or limit stop that must win over the PHP throw.
- Caching an evaluated parameter default: cache per run in `vmState.defaults`, never in `Program`. PHP keeps a default across calls only when the value is not refcounted (null, bool, int, float, empty array, interned strings), so a warning from the default prints on the first call only. `Compile` refuses defaults whose result depends on interning. This rule is inferred from probes, not read from Zend source.
- Choosing which lazy operand `==` initialises first: it follows the C compiler of the PHP build (left first on linux/arm64 and macOS, right first on linux/amd64, linux/386 and Windows x64), which is why the heap profile is (width, arch, os). Measure any new behaviour that depends on C argument order on `macos-15-intel` and `windows-2025` through the Host profile workflow.

## Output and shutdown

- Routing displayed errors with `display_errors=1`: they go through the output layer. A write while a handler runs flags the buffer that receives it, the handler-output deprecation is raised after the running handler is disabled so its text lands in the next buffer down, and an uncaught error from a handler at request shutdown is discarded. Test with a closure, not `ob_start("strtoupper")`, which fails on argument count.
- Skipping destructors after a fatal: mark only the objects alive at that moment; objects created later in shutdown callbacks destruct normally. Do not run `heap.shutdown` before the output flush, because output callbacks create and destroy objects. Frame locals release in variable order and keep unwinding after a destructor throws.
- Output from inside a user output handler: it goes into the handler's own buffer, and the deprecation needs a returned value, so a handler stopped by its own fatal, exit or throw does not get it. Any `ob_*` call inside a handler discards every buffer. Do not infer the exit rule from the fatal rule, and use the `solo_` fixtures, because `common.php` always adds two outer buffers that hide single-buffer shutdown behaviour.

## Arrays and sorting

- Iterating by reference over an array that gets copied: keep a position per iterator across the candidate copy-on-write copies. Do not separate shared copies on each fetch, which turns the previous item's temporary reference into a permanent alias. When a known copy becomes the selected one, prune the other candidates; advance the source cursor before binding the next item.
- Inserting a numeric key beyond the packed range: pre-grow only when the old `used >= limit`, before compacting, because an exhausted internal pointer exposes the logical packed capacity even after sorting and copy-on-write. Keep this out of the generic `toIndexed`; string keys, earlier holes, sort conversion and non-full numeric conversion do not pre-grow.
- Sorting: use the schedule ported from `zend_sort.c` with the original-position stable fallback, never a generic Go stable sort. Callback orientation, call count and the partial permutation after an exception are all observable. A user callback exception stops user calls while internal comparisons continue. Native sort separates and mutates in place; user sort duplicates and commits to a captured reference.
- Calling a user sort callback: retain each invocation's arguments independently, retain the raw return before releasing the arguments, and release it on every error path. After a bool `false` retry, reload the live bucket locations. A destructor error during argument cleanup keeps a valid numeric result but suppresses warnings and the retry.

## Objects: ownership and lifetimes

- Releasing dynamic property slots: do not move live entries or reuse deleted addresses. Sweep only entirely empty blocks, at the outermost exit of an iteration or comparison, including on panic. Evidence is `W-13-r9-review.json`.
- Setting the retirement sweep threshold: round it up to the 16-entry block quantum and saturate the counter; a threshold of live+16 swept every 17 deletes. Measure Go 386 header cost on a real 386 binary, not from the PHP 32-bit profile.
- Holding operands during comparison or a hook: use individual `methodHold` stack values, not slices. Comparison holds left then right and releases in that order; a hook retains the receiver first, then captures the raw right-hand value, and protects the output before cleanup. Merge every cleanup error.
- Moving a constructor temporary (reference count 0) into a mutable array or reference location: take the location's owner first. Snapshot both raw locations' original zero counts before promoting either, and count a self-pointer once; otherwise `bind(o, o)` destroys its live target.
- Returning by value from a magic method or hook: dereference before `ownReturn`, protect the target and discard the temporary wrapper. A by-reference callback binding retains exactly one destination owner. Consume ignored set/unset/isset/clone results at the use site.
- Coercing a method or getter return: hold the raw value during weak conversion, because `__toString` can unset its last external owner; `checkMethodReturn` consumes a rejected or coerced-away raw value once. A throw during return conversion becomes a return `TypeError` with the original as previous; a throw during argument conversion stays the original exception.
- Verifying a return type: do it inside the callee callback, before locals destruct, then `ownReturn` and unwind. A by-reference return from a typed-property source with a mismatched declared type is rejected before any coercion. Validate callables with the request-aware `isObjectCallable` before the typed-sources guard.
- Closing a resource: commit closed/freed state first, hold the identity through the callback and through recovered panic formatting, release at the end of the defer, then delete the registry entry only when it really has zero owners. Close callbacks can reacquire closed aliases.
- After a lazy initializer's holds are cleaned up: check whether the original wrapper was freed only when no error is pending; a live external backing does not rescue a freed wrapper. A captured variable nulled in the initializer makes every property operation raise "Lazy object was released during initialization".
- Matching PHP's garbage-collection order: root-buffer holes are reused last-in-first-out with tail compaction, and active foreach and live-range values are re-buffered after collection, in frame order. Sorting roots or rescanning the original white set does not match. Do not drop events to make a sequence pass.

## Objects: properties, hooks and references

- Reporting an asymmetric-visibility error: the access decision uses the lexical scope, the message uses the called scope. Keep `currentCalledScope` request-local, set and restored across the whole invocation frame including local cleanup. `private(set)` readonly errors omit the readonly qualifier.
- Taking a reference to a hooked property: run a by-value getter once; an object result allows a detached reference, while a scalar, array or null result raises "Indirect modification" with the receiver's class. A setter-only backed property that is uninitialised raises the typed-uninitialised error first. Rejecting every hook, or rejecting before the getter runs, both fail on PHP.
- Removing a typed reference source: identify the declaration by pointer, and when that fails by non-nil declaring owner plus storage key, because `buildClass` clones inherited `propertyInfo` values while PHP shares them. Do not use `prototypeOwner`, which survives real redeclarations.
- Reading or writing raw property state: use the resolved `propertyInfo.key`, never the name; a parent private and a child property of the same name are different slots. Retain the dereferenced receiver and right-hand values rather than their reference containers, because `__toString` can rebind aliases.
- After coercing the first assignment to a readonly property: revalidate that the receiver is alive and refetch the slot, but do not repeat the readonly qualification check. PHP commits the outer assignment even when `__toString` initialised the property in between.
- Accepting a `self` or `parent` type on a reference: resolve it against the property's owner, as `coerceProperty` does. "May coerce" is a verifier phase and not proof the conversion succeeds; keep PHP's ordering and do not add extra `TypeError` previous chains.
- Assigning through a typed reference: validate against the original reference sources, store through the reference as it is currently bound, and do not re-run type validation for a rebound destination. Hold the original reference and the borrowed right-hand value during callbacks. Tests must use the real cell pointers, because copied cells hide the defect.
- Passing a typed-property reference to a by-reference parameter of another type: reject before any conversion or body execution, even for `mixed`. Untyped references still coerce and write back. Check callable acceptance before rejecting typed sources.
- Mutating the typed-source list while `__toString` runs: do not clear entries with `slices.DeleteFunc`. PHP captures the initial extent but reads current cells; removal swaps the last entry into the first match, and the list shrinks at a quarter full. Behaviour across reallocation is unverified.
- Validating a setter hook's input: use the setter parameter's type and name, not the backing type. Take the receiver and raw right-hand holds before coercion, and enable `currentHook` only after preparation, inside the cleared callback frame. Build the synthetic method name only when a `TypeError` is raised.
- Naming a getter in an error: build the `$name::get` label only in the two error formatters. Allocating it before successful return validation cost one allocation per read.
- Handling `unset` on a property: deny hooked, readonly and setter access before lazy initialisation, leave initialised raw slots alone, and revalidate after any pending initialisation ends or the proxy target changes. Receiver pointer equality does not prove nothing changed, because a ghost initialises in place.
- Numbering a variadic parameter error: the number is the variadic declaration index plus the count of earlier positional variadic arguments; named arguments do not advance it, and the message omits the parameter name.
- Binding a property reference after a forwarded getter guard: restore the guard before binding the destination, and clear stack ownership before the delete so the deferred restore runs once. Keeping the guard through the bind suppresses a getter that the old destination's destructor calls.

## Objects: lazy objects and proxies

- Tracking lazy state: use per-slot flags keyed by storage key plus a remaining counter, and do not derive either from value kinds or map sizes. Raw writes during a running proxy factory do not decrement the counter, and a failed factory leaves flags and counter diverged, as PHP does.
- Snapshotting a ghost's non-lazy flags: share the map pointer and restore it on failure; the map is immutable while the initializer runs. Cleanup sets the field to nil instead of `clear(map)`. Recheck this if a new producer of the flags appears.
- Observing lazy state in a test: use `isLazy`; `ReflectionProperty::isInitialized` on an untouched lazy inherited-private property triggers the initializer. Do not weaken expected rollback events without a trace that isolates the cause.
- After raw-set then unset on a lazy object: read, isset and reference do not initialise it; a write without `__set` still does. Magic methods run first.
- Forwarding magic guards across a lazy proxy: forward only on the operation-specific transition. Declared get, reference and unset can call magic twice after initialisation; set and isset suppress recursion on the target; absent dynamic properties keep the wrapper's magic.
- Resolving a property on an initialised proxy: keep the wrapper's hooks and re-resolve the target's metadata only after the backing changes. The static-accessed-as-instance notice uses the receiver's class, and the existence of the associated magic method suppresses it even when the guard blocks the call.
- Rolling back a failed lazy initializer: restore in one filtered schema traversal in physical slot order, keeping the per-slot sequence (detach, release or callback, snapshot transfer, add descriptor). Rebuilding the registry in a batch changes the observable source order.
- Comparing two objects of the same class: decide direct-slot eligibility before any lazy initialisation. Declared slots compare in order and one uninitialised slot returns 1 in either direction; after `get_object_vars`, casts, dynamic slots or lazy comparison, hash semantics apply and the materialised state is kept through clone and rollback.
- Comparing WeakMaps: return equal after the identity and class checks. PHP uses the standard empty-property comparison and ignores entries, so do not add a content walk.

## Objects: classes, methods and callables

- Walking the interface graph in `classIs`: use the iterative depth-first search that memoises only fully explored misses. The graph is acyclic; visiting-on-entry allocated on first-path success, and plain recursion re-expanded diamonds. Do not add a permanent transitive closure or shared mutable state.
- Composing traits: bind traits before inheritance. Only a collision with a property the consuming class itself declares is strict; an inherited non-private property follows ordinary replacement, and an ancestor's private stays separate. The first setter visibility wins.
- Deciding whether a bare object is callable: look up the effective `__invoke` on the receiver's class and ignore its visibility; `__call` alone does not make a bare object callable. Strict-types cases need a real `declare(strict_types=1)` file.
- Resolving `__call` and `__callStatic`: use the receiver's effective handler with no lexical scope and no visibility gate, including the fallback for an inaccessible explicit `__call`. `is_callable` ignores handler visibility too. Pass arguments positionally, never as named arguments.
- Validating a relative callable (`self`, `parent`, `static`): use the callee's lexical scope, the actual called class and whether the callee has `$this`, not the caller's scope. The deprecation fires exactly once after class resolution, even when the method is invalid; a leading backslash is not relative.
- Changing a diagnostic harness under `engineering/implementation/evidence/`: archive the input versions of each recorded run with their hashes. A later change to a shared helper made a recorded output impossible to replay until the original sources were recovered.
