# Rules for `internal/ir`

Each line is a condition and what to do. The story behind a line is in the commit that added it (`git log -S '<words from the line>'`).

- Checking a compile-time error against PHP: `TOKEN_PARSE` does not cover `zend_compile` errors, so run `php -n -d display_errors=1 -d error_reporting=-1 -l` on each corpus file in the pinned image and read the output with `grep -a`. Conditions and messages are in `Zend/zend_compile.c` of the locked archive.
- Adding a node anywhere in lowering: pass every node you build through `l.seal`. An unsealed node reports no effects and hides the effects of everything inside it from the enclosing `if`, loop or `try`; `TestControlFlowBodiesCarryTheirEffects` guards this.
- Changing constant evaluation: keep it linear in source size, and keep `TestConstantEvaluationScalesLinearly` passing. The working design is one iterative spine over the first operand, a `strings.Builder` per run of concatenations, a per-expression budget plus a unit-wide reserve, probes that share the expression memo, and prescans that skip closure and function bodies. Per-step charging, recursion per kind switch, fixed memo caps and per-operand memo rebuilds each rejected valid PHP.
- Reporting the line of a compile error: PHP uses the line of the expression compiled last, and a node with operands takes the line of its first operand, which `l.cur` and `zline()` track. A constant array folded at compile time keeps the array's line, and the second compilation of a `??=` target starts at the name expression. PHP skips compiling the right side of `&&`/`||` after a constant left operand. Verify each expected line with `php -l` in the pinned image before changing it.
- Adding a check on constant expressions: put it in `syntaxConstantValue`, which follows PHP's order (an eval pass, then a compile pass in preorder) and its selection of branches, and report at `l.cur`. A separate pre-walk over the frontend tree walked unselected branches, entered nodes PHP does not evaluate and crashed on `class_const` declarations. Scanner diagnostics come before compile diagnostics in token order, so collect decode warnings per node and emit both in one preorder walk.
